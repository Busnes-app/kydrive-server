# M3 Sharing Implementation Plan

> **For agentic workers:** execute task by task, failing test first. Ship as a stack of PRs: A (M3.1), B (M3.2–3.4), C (M3.5), D (M3.6). Each PR leaves `master` releasable.

**Goal:** a folder-level grant gives exactly that subtree; removing a group from KyIdentity revokes an open editor on a folder-shared file within one revocation tick; an expired or revoked link returns 404; a guest link never reveals sibling files.

**Spec:** `docs/superpowers/plans/2026-10-07-onedrive-parity-roadmap.md` M3 and the 2026-10-07 decisions (people, per-folder permissions, organisation links, external guest links).

## Decisions

1. **One access definition** (`internal/drive/access.go`): a Go-built SQL rank expression, `rank(user, workspace, folder, file)` → 0–3, used by every check: `authorize`, `Workspaces`, `PendingRevocations`, listings and the new share checks. No other SQL may compute access.
2. **Workspace grants stay in `drive_grants`.** Item shares go in a new `drive_shares` table instead of migrating `drive_grants` (no data migration on a live table); the single definition reads both. Deviation from the roadmap's "generalise drive_grants", same effect.
3. **Effective rank** = max(workspace rank, every share on the item or any ancestor folder) for the user directly, their active groups, or (M3.5) an organisation link they opened. Shares only add; nothing narrows.
4. **Who shares:** a manager of the item (effective rank 3, including a personal owner). Editors share up to their own role only when the workspace's `editors_share` setting is on (off by default, manager-set). Readers never share.
5. **People picker:** `GET /api/drive/people?q=` (signed-in users only, active accounts, 2+ characters, 20 results, display name and username, never email) so non-admins can pick a person. Groups come from the existing workspace directory.
6. **Personal workspaces:** the owner can share items; a deactivated owner's shares stop working (the owner check is part of the definition) until handover moves the items; handover drops the shares and audits it.
7. **Shared with me:** items shared to the user or their groups in workspaces where the user has no workspace grant, newest first.
8. **WebDAV shows workspaces only.** Items shared outside your workspaces are web-only in M3; documented. `FolderTree` (zip) needs no per-member check: shares only add, so every member's rank is at least the root's.
9. **Organisation links (M3.5):** 256-bit token shown once (copy), stored as SHA-256, resolving to item + role (reader or editor) for any active signed-in user; optional expiry; revocable; opening records `(link, user)` and audits; access through the link ends when it is revoked or expires.
10. **Guest links (M3.6):** off suite-wide until an admin enables them. Read/download only, mandatory expiry (default 7 days, admin maximum, default 30), optional password (`ky-primitives/password`, 5 attempts per 15 minutes per link and per IP), optional upload-only "request files" mode into one folder with a per-file cap. Served under `/api/public/links/` and `/g/<token>` with `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`, no session cookie, and the token never logged.

## Review Focus

1. A share leaking siblings or parents: a folder share reaches its subtree only (`TestFolderShareScope`).
2. Revocation: removing a user from a shared group revokes their editor on a folder-shared file in one `PendingRevocations` pass (`TestShareRevocationRevokesEditor`).
3. Behaviour drift in M3.1: every current rule pinned before the refactor (`TestAccessDefinitionPinsCurrentRules`).
4. Links: expired or revoked → 404, guest sees only the shared item, wrong passwords are rate-limited, token never in logs.

### PR A — M3.1 single access definition

- [ ] `TestAccessDefinitionPinsCurrentRules` (table-driven, before any change): personal owner active/inactive, group grant reader/editor/manager, inactive member, grant on a personal workspace ignored, service token scope and rank, `Workspaces` roles, `PendingRevocations` keeping a read-only session on a reader grant and revoking an editable one.
- [ ] `access.go`: `rankSQL(user, workspace string) string` returning the expression; `authorize`, `Workspaces` and `PendingRevocations` use it. Delete the three copies.
- [ ] Contract: `internal/drive/AGENTS.md` names `access.go` as the only place access is computed.

### PR B — M3.2–3.4 item shares, personal sharing, shared with me

- Schema: `drive_shares(id, workspace, resource_kind folder|file, resource_id, principal_kind group|user|link, principal_id, role reader|editor|manager, created_by, created, expires)`, unique `(resource_kind, resource_id, principal_kind, principal_id)`; `drive_workspaces.editors_share`.
- `rankSQL` grows to `rankSQL(user, workspace, folder, file)` walking ancestors with a recursive CTE.
- Store: `Share`, `Unshare`, `Shares(item)`, `SharedWithMe`, `People(q)`; every item check uses the item form: `File`, `Children`, `Lookup`, mutations (parent folder for create/move target, item for trash/rename/purge), uploads, editor sessions, `PendingRevocations` (per file).
- A user with item access but no workspace access sees the workspace only through Shared with me; `Workspaces` is unchanged; `Files`/`Folders` of a whole workspace stay workspace-rank only.
- Handover drops shares on the moved items (audited).
- API: `GET/PUT/DELETE /api/drive/{files|folders}/{id}/shares`, `GET /api/drive/shared-with-me`, `GET /api/drive/people`, workspace `editors_share` setting.
- Web: Share dialog on file and folder menus (people and groups, role, remove); Shared with me sidebar entry; navigation inside a shared folder.
- Tests: `TestFolderShareScope`, `TestShareRolesAndWhoCanShare`, `TestPersonalShareStopsWhenOwnerDeactivated`, `TestShareRevocationRevokesEditor`, `TestSharedWithMe`, `TestPeopleSearch`, handover drops shares; vitest for the dialog; Playwright: share a folder with a second user who opens it from Shared with me.

### PR C — M3.5 organisation links

- `drive_links(id, workspace, resource_kind, resource_id, role, token_hash, scope org|guest, expires, password_hash, upload_only, created_by, created, revoked)`, `drive_link_users(link, user, opened)`.
- `rankSQL` counts `drive_shares` rows with `principal_kind='link'` for users in `drive_link_users` while the link is live.
- Routes: create/list/revoke on the item, `POST /api/drive/links/open` with the token in the body (never in a URL the server logs), SPA route `/l/<token>` reading it from the fragment.
- Tests: open, revoke → 404 and access gone, expiry, audit rows.

### PR D — M3.6 guest links

- Admin setting (off), maximum expiry; guest routes as in Decision 10; guest page (view/download, or upload-only drop zone) with no app chrome.
- Tests: disabled → 404, siblings unreachable, password and rate limit, headers, token absent from logs, upload-only cannot list.
