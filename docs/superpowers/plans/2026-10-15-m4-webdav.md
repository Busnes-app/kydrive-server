# M4 WebDAV Implementation Plan

> **For agentic workers:** execute task by task; steps use checkbox (`- [ ]`) syntax. Write each failing test first, watch it fail, then implement.

**Goal:** a workspace mounts in Windows, macOS and Linux file managers; saving from LibreOffice over WebDAV creates a new version; a deactivated user's app password stops working on its next request.

**Architecture:** `golang.org/x/net/webdav` serves `/dav/` with a custom `webdav.FileSystem` (new package `internal/dav`) built per request over the drive store, and one in-memory `LockSystem` per server. Paths resolve one segment at a time through an equality lookup on the existing `name_hmac` index, so no request lists a whole workspace. Users authenticate with per-user **app passwords** over HTTP Basic, accepted only on `/dav/`.

**Spec:** `docs/superpowers/plans/2026-10-07-onedrive-parity-roadmap.md` milestone M4. Contracts: `AGENTS.md`, `internal/drive/AGENTS.md`, `internal/api/AGENTS.md`, `internal/auth/AGENTS.md`, `web/AGENTS.md`.

**Builds on M2** (merged in #26, completion claim in #27): WebDAV `PUT` reuses `KYDRIVE_MAX_FILE_SIZE` and M2's body-limit pattern.

## Decisions

1. **App passwords** are 160-bit random secrets shown once, formatted `xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx` (base32, no padding) so they can be typed. Stored as SHA-256 like service tokens (high-entropy secrets need no slow hash). Named, at most 20 per user, no expiry, revocable, last use recorded at most every 5 minutes. They live in the drive schema because only `/dav/` accepts them.
2. **Basic auth username** must equal the account's username (case-insensitive) and the password must be one of its live app passwords. The account must be `active` on every request, so deactivation stops it at once without deleting anything.
3. **Never on any other route.** App passwords authenticate `/dav/` only; `/api/*` keeps cookie sessions and drive service tokens. Creating, listing and revoking app passwords needs a cookie session (`/api/auth/app-passwords`); service tokens and installer admins are refused.
4. **HTTPS only:** Basic credentials are refused unless the request arrived over TLS (directly, or from a trusted proxy's `X-Forwarded-Proto`), except with `KY_ENV=development`. The refusal never echoes the credential.
5. **Browser cross-site refusal:** every `/dav/` request runs `sameSiteRequest` (refuses foreign `Origin` or `Sec-Fetch-Site`), because browsers resend cached Basic credentials ambiently. Native clients send neither header. Cookies are ignored on `/dav/`.
6. **Failed Basic attempts** are rate-limited per client IP (20 per minute) and per username (10 per 15 minutes), the login limits.
7. **Paths:** `/dav/` lists readable workspaces by name; duplicates get ` (2)`, ` (3)` by workspace ID order. Workspaces cannot be created, renamed or deleted over WebDAV (403).
8. **Mapping:** `MKCOL` → `AddFolder`; `DELETE` → `SetTrash`/`SetFolderTrash` (never purge); `MOVE` → `MoveFile` (cross-workspace by the M1 manager rule) / `MoveFolder` (same workspace only, else 403); `PUT` → `WriteBlob` + `Publish`. `If-Match` against the ETag `"<revision>"` gives 412 on mismatch; without it, last writer wins and the overwritten revision stays in history.
9. **COPY** uses x/net's generic copy (read source, write destination through `PUT` mapping) instead of `CopyFile`. Same result for the user; the copy gets its own blob. Revisit only if blob duplication is measured to matter.
10. **PROPPATCH** of dead properties (Windows sets `Win32*` times) is accepted and discarded, so Explorer copies do not fail. Nothing is stored.
11. **Locks** are x/net's in-memory `LockSystem`: single instance, lost on restart (clients re-lock).
12. **Size:** `PUT` bodies are capped at `KYDRIVE_MAX_FILE_SIZE`; a single `PUT` must finish within `KY_READ_TIMEOUT` (≤ 15 m). Windows' own 50 MB WebDAV default is documented in the README with the registry fix.

## Global Constraints

- Read the DOX chain first. SQLite only; drive schema entries append-only.
- Domain code (`internal/drive`) stays HTTP-free; `internal/dav` depends on `internal/drive`, not on `internal/api`.
- Every state change writes a `drive_events` row (app password created/revoked; file operations already do).
- Names are never filtered in SQL except by `name_hmac` equality, which the unique index already supports.
- New dependency: `golang.org/x/net` (webdav only). No npm additions.
- Run Go tests in a capped scope.

## Review Focus

1. **Credential acceptance.** Expected: app passwords only on `/dav/`, only over HTTPS (or development), only for an active user whose username matches, never as a cookie substitute. Pinned by `TestDAVAuthentication`.
2. **Path traversal or a name resolving to another workspace's item.** Expected: every lookup is scoped to the resolved workspace and parent, and every operation re-authorizes inside the store. Pinned by `TestDAVScopesEveryLookup`.
3. **DELETE purging data.** Expected: it trashes; restore works. Pinned by `TestDAVDeleteTrashes`.
4. **A write losing data.** Expected: an interrupted `PUT` publishes nothing; a conflicting `If-Match` publishes nothing; a last-writer-wins overwrite keeps the old revision. Pinned by `TestDAVPut`.

### Task 4: The WebDAV file system

**Files:** create `internal/dav/fs.go`, `internal/dav/fs_test.go`, `internal/dav/AGENTS.md`.

- `func New(store *drive.Store, user string, blobs string, key []byte, maxFile int64) webdav.FileSystem`, built per request (it caches the workspace list for that request only).
- Path resolution: `/` → workspaces; `/<ws>/a/b` → `Lookup` per segment. Clean paths with `path.Clean`; reject segments failing `ValidName`.
- `Stat`/`OpenFile` read: `os.FileInfo` with size, version time, `ETag` `"<revision>"` (`webdav.ETager`), `ContentType` from the extension (`webdav.ContentTyper`) so no content sniffing reads the blob. Reads use `OpenBlob` (seekable, so Range works).
- `OpenFile` write: a pipe into `WriteBlob` in a goroutine; `Close` waits, then `Publish` against the revision seen at open (`If-Match` checked by the HTTP layer first). A `Publish` conflict without `If-Match` retries against the newest revision (last writer wins); a failed write or publish discards the blob. A `Write` after an error returns it.
- `Mkdir`, `RemoveAll`, `Rename` per Decisions 7–8; errors map to `os.ErrNotExist`, `os.ErrPermission`, `os.ErrExist` so x/net picks the right status.
- Dead properties: a `DeadPropsHolder` that accepts and drops patches.
- [ ] Tests (through `webdav.Handler` and `httptest`, real store and blobs): `PROPFIND` depth 1 at `/`, a workspace and a folder; duplicate workspace names suffixed; `PUT` new file, overwrite (revision 2, history keeps 1), `If-Match` stale → 412 with no version, interrupted body → no version; `GET` and `Range`; `MKCOL`; `MOVE` rename, into a folder, across workspaces (manager vs editor); `COPY`; `DELETE` → trash then restorable; `LOCK`/`UNLOCK`; reader gets 403 on `PUT`; names with spaces and non-ASCII.

### Task 5: Mount `/dav/` with Basic auth

**Files:** create `internal/api/dav.go`, `internal/api/dav_test.go`; modify `internal/api/server.go` (dispatch `/dav/` before the generic OPTIONS/CSRF block, body limit), `internal/api/AGENTS.md`, `internal/auth/AGENTS.md`, root `AGENTS.md:107`.

- Order: security headers → `sameSiteRequest` (403) → HTTPS rule (403 "WebDAV requires HTTPS") → Basic credentials (401 with `WWW-Authenticate: Basic realm="KyDrive", charset="UTF-8"`) with the failure rate limit (429) → `AppPasswordUser` → load user → `webdav.Handler{Prefix: "/dav", FileSystem: dav.New(...), LockSystem: s.davLocks}`.
- `If-Match` on `PUT` checked here against the current ETag before the handler runs.
- Body limit for `/dav/` `PUT`: `KYDRIVE_MAX_FILE_SIZE + 1`; others 1 MiB.
- Responses carry `Cache-Control: no-store`; the CSP stays.
