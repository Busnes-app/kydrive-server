# M5 Previews and Thumbnails Implementation Plan

> **For agentic workers:** execute task by task, failing test first. Ship as a stack of PRs: A (preview), B (image thumbnails), C (Office and PDF thumbnails). Each PR leaves `master` releasable.

**Goal:** previews render for the allowlist; an HTML or SVG upload downloads instead of rendering; a decompression-bomb PNG is refused without a large allocation.

**Spec:** `docs/superpowers/plans/2026-10-07-onedrive-parity-roadmap.md` M5. Contracts: `AGENTS.md`, `internal/drive/AGENTS.md`, `internal/api/AGENTS.md`, `internal/editor/AGENTS.md`, `web/AGENTS.md`.

## Decisions

1. **The bytes decide, never the name.** The preview type is `http.DetectContentType` of the first 512 plaintext bytes, served only if it is on the allowlist: `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `application/pdf`, `audio/mpeg`, `audio/wave`, `application/ogg`, `video/mp4`, `video/webm`, `text/plain; charset=utf-8`. Everything else (HTML, SVG, XML, scripts, UTF-16 text) answers 415 and the client offers Download. A `.png` holding HTML sniffs as HTML and is refused; markup without an HTML or XML signature (a `.txt` with tags, an SVG without `<?xml`) sniffs as text and is shown as its source, sandboxed and `nosniff`.
2. **One preview route:** `GET /api/drive/files/{id}/preview` (reader rights, current revision, `HEAD` and `Range` through `http.ServeContent`). Headers: the sniffed type, `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self'; media-src 'self'; style-src 'unsafe-inline'; frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN` (PDFs are framed by the app), `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: no-store` (a revoked share stops at once).
3. **PDF in a sandbox.** Chromium's viewer renders a PDF served with `CSP: sandbox`, top level and in a same-origin iframe (probed 2026-10-16). Firefox is unverified; if its viewer refuses, the modal still offers Open in new tab and Download.
4. **Quick look** is a `<dialog>` in the drive page: image `<img>`, PDF `<iframe>`, audio and video elements, text fetched with `Range: bytes=0-262143` into a `<pre>` (React escapes it) with a "first 256 KiB" note when cut. The type comes from a `HEAD` on the preview route; 415 shows "No preview" with Download.
5. **Opening a file:** the name opens Euro-Office for its formats except PDF, the whiteboard for `.excalidraw`, and quick look for everything else (today those open an editor that refuses them). Every live file's menu gains Preview.
6. **Thumbnails (B):** `GET /api/drive/files/{id}/thumbnail` returns a PNG inside 256×256. Raster PNG, JPEG, GIF (first frame) and WebP (`golang.org/x/image`, the one new dependency) up to 64 MiB, whose `image.DecodeConfig` reports at most 8192 px a side and 40 megapixels, else 415, checked before decoding. At most two thumbnails are decoded at once.
7. **Thumbnail cache:** `<data>/thumbs/<blob>`, sealed with the blob key like every blob (a plaintext thumbnail would undo encryption at rest), named by blob ID rather than digest (a digest name would let a disk reader confirm known content). Derived, outside backups (backups copy referenced blobs only), safe to delete; the hourly orphan sweep removes thumbnails whose blob is gone.
8. **Office and PDF thumbnails (C):** Euro-Office's conversion service renders the first page to PNG. KyDrive posts a signed conversion request whose source URL carries a short-lived HMAC ticket for that one blob; the Document Server's fetch is checked like editor downloads (outbox JWT bound to the URL); the result is fetched through the existing restricted `Fetch`. Without Euro-Office these show their type icon.
9. **Type icons:** the list shows a small icon per kind (folder, image, PDF, document, spreadsheet, presentation, whiteboard, audio, video, other); thumbnails replace the icon when they load.

## Review Focus

1. Active content rendering on the app origin: only sniffed allowlist types, always sandboxed and `nosniff` (`TestPreviewServesOnlyTheAllowlist`).
2. Decompression bombs: refused from `DecodeConfig` before any pixel allocation (`TestThumbnailRefusesBombs`).
3. Plaintext left on disk: thumbnails are sealed and named by blob ID (`TestThumbnailCacheIsSealed`).
4. Access: preview and thumbnail need the same rights as download, including shares and revocation.
