## Findings (smallest material first)

- **F1** (minor-material, all light captures with text fields or selects (login, search, share, new folder, account)): Field borders sample (163,165,163) and (167,171,172): ~2.29-2.48:1 against white and ~2.14-2.32:1 against cream. Dark borders sample 3.24-3.84:1. The pinned --ky-field-border mix would compute to about 3.3-3.6:1 in light. Fix: Give inputs, selects and the search field the shared --ky-field-border in light.
- **F2** (minor-material, files/folder toolbar and rows, account region sign-out, dialog close): The refresh, row '...' and sign-out buttons are 36px. Icon buttons use a fainter border, (204,207,207) at ~1.6:1 in light and ~2.0:1 in dark, than the 40px text buttons such as New and Download. Fix: Make icon buttons 40px and give them the text-button outline.
- **F3** (minor, files/folder): The list card header repeats the h1 'My files', and the folder subtitle 'My files' repeats the breadcrumb directly below it. Fix: Drop the duplicate card label or subtitle when it equals the page title or breadcrumb.
- **F4** (minor, trash): The trash card header band is page-background tinted, while the Files card header is panel-coloured. As a result Empty trash has a tinted fill and Delete permanently a panel fill. Fix: Use the same card-header surface as Files.
- **F5** (minor, account): The moved 'Files / Open files in a new tab' preference sits uncarded above two bordered cards. Fix: Put it in a titled card like the other groups, or make all sections flat.
- **F6** (minor, preview): About 80-85% of the bounded body is empty for the three-line fixture. On phone, Download ends at x=329 while the close button ends at x=354. Fix: Keep the bounded height (parent rationale accepted), but right-align or stretch the phone action row to the close edge.
- **F7** (minor, login): 'Security check verified.' is a separately bordered box inside the bordered card, and the native theme select floats in the page corner. Fix: Render the status as an unboxed inline status line.
- **F8** (minor, appearance phone): On initial view the selected Appearance chip's fill runs to x=389, flush with the viewport edge, and My files is scrolled off-screen. Fix: Add end padding to the scrolling nav so the selected chip keeps an inset.
- **F9** (behaviour (unscored), phone keyboard navigation): Capture provenance records that native phone Tab can leave Appearance 117.69px clipped and the Settings focus ring 1.78px clipped in both schemes. Not visible in any PNG, so not scored. The parent is fixing focus-only row scrolling separately. Fix: Scroll the focused nav row into view with inline padding on focus; re-probe both schemes.
- **F10** (observation, share): No action reads as primary: Create link and Done are equal-weight outlines. I scored hierarchy 7 on that visible fact. I do not require a filled orange button: Done dismisses and Create link is optional, as the parent argues. Fix: None required. Optional: give the person search more visual lead.

## Prior objections (judged on pixels)

- Phone header identity/navigation cues; preference occupying a shell row: Resolved in pixels. The phone header shows name and role, a plain 'Scroll for more destinations' hint appears, and the preference is no longer in the shell; it now sits in Account > Files (see F5 for its containment).
- Preview control sizes / nested frame: Resolved: link, Download and close share one 40px row, and the text body is flat with no inner frame. Remaining: mostly empty body, ragged phone action row (F6).
- Help below Access instead of the person field: Resolved: help sits directly below the person input, and 'Organization' is spelled consistently.
- Search/list width and Upload/title alignment: Resolved: search spans x=280-1240, matching the card, and Upload's top aligns with the title.
- Inconsistent Trash control size/prominence: Largely resolved: Back to files comes first, Empty trash is an outline, and row actions are 40px. The tinted header band still gives the two danger buttons different fills (F4).
- Native selects unstyled: Pixel sampling shows the selects and the text input share fill and border exactly. Native arrows alone are not penalised.
- Done/Create link not a filled primary: Parent position accepted (F10). Hierarchy 7 reflects the visible equal weighting, not a demand for orange.
