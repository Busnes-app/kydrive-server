## Specific Opus claims against baseline

- **M1 — admin panels dominate initial phone files:** supported for this administrator fixture. Three closed administrative panels occupy approximately y279–479 before search at y499 and file panel at y559 in both themes. Files still shows two complete rows and a sliver of the next; folder icon and **This folder is empty heading remain visible near y770–830**. “Push the list or empty state below the fold” is too absolute if read as entirely invisible. Displacement is factual; how dominant it feels is judgment. Baseline `web/src/App.tsx:167` passes the admin-role flag; `web/src/pages/Drive.tsx:264–284` puts the admin block before Search/files and guards it with `admin`. Do not extrapolate to ordinary users.
- **M2 — My files title inside folder/Trash:** supported across inspected desktop/phone light/dark originals. Workspace h1 stays My files while Project materials is in the breadcrumb and Trash in a subordinate banner. **Not globally hard-coded:** `web/src/pages/Drive.tsx:257` uses `current?.name`; `:181–182` constructs folder breadcrumbs and `:173–174` the Trash heading. Prioritizing workspace versus folder/task is a hierarchy choice, not evidence the location is wholly unidentified.
- **M3 — Account alignment/two orange/faded disabled/dashed rule:** desktop facts supported. x≈384 versus x≈280 comes from centered `.page` plus `.page-narrow` max-width (`web/src/styles/theme.css:178–179`, `web/src/App.tsx:172`). Its own cards/headings align consistently; centering is not inherently broken. Desktop has two accent-derived buttons but only MFA is enabled/strongly emphasized. Empty-name creation is disabled (`web/src/pages/AppPasswords.tsx:97–99`), and `theme.css:201–212` merely halves opacity: this conflicts directly with the pinned contract’s “not just be a faded primary.” The dashed line is **the empty-note paragraph’s border**, not the h3 (`AppPasswords.tsx:102–104`, `theme.css:302`); its removal is taste. Both phone originals end before these elements, so source existence is not phone visual evidence.
- **M4 — duplicate empty-upload primaries:** supported in both desktop folder originals. Toolbar and empty-state Upload files buttons share fill and open the same input (`web/src/pages/Drive.tsx:191`, `:213–217`). This is duplicate emphasis for one action, not competing task outcomes. Phone shows only toolbar Upload; do not claim two visible buttons there.
- **M5 — clipped Trash card corners:** interrupted upper corner outlines visible in all four original Trash images; content/actions intact. `.panel` rounds the parent (`theme.css:188`), `.drive-files-panel` has `overflow:visible` (`:349`), and `.drive-trash-banner` paints a square page-colored background without its own radius (`:360`). This is consistent with child background painting across the parent’s rounded contour. “Clipping” is loose visual wording, not established viewport overflow/cropped content/hit-area failure. Sol’s header-fill explanation omits the actual corner discontinuity.
- **M6 — decorative orange folder icon / Current badge:** orange folder **strokes inside a neutral tile** appear in all four files originals; it is not a solid orange tile. Baseline `web/src/pages/drive/FileIcon.tsx:38–39` supplies a meaningful type glyph; `theme.css:384–385` gives it unconditional accent ink. The glyph is useful, but orange is not selection/action/focus here: strict accent-discipline concern supported. Current is meaningful status on the actual current revision (`web/src/pages/drive/Versions.tsx:19–21`, `theme.css:280–281`), not arbitrary decoration. Sol’s active-state reading versus Opus’s status-role objection remains a semantic design disagreement, separate from brand-neutral color quality; neither vector is amended.

**Off-base/overbroad interpretation:** treating checked preferences or selected radio cards as forbidden accent roles. The pinned contract expressly permits selected states. This qualifies phone Account’s “three roles” rationale and desktop folder’s checkbox count, without negating duplicate Upload or faded-primary evidence. Grey-filled dark radios do look different from light empty rings, but “can read as disabled” is a perception, not actual disabled state: `web/src/pages/Appearance.tsx:19–20` has checked/onChange without disabled; native styling is `web/src/ky-ui/appearance.css:63–74`. Operation/persistence remain untested.
