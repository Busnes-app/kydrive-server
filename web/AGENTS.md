# Web

## Purpose
React 19 + TypeScript + Vite PWA frontend embedding KySecurity color tokens (Busnes light/dark defaults plus `Patina Ky`, `Cyber`, `Nord`, `Paper`, `OLED`), client-side WebCrypto PoW CAPTCHA, and administrative management panels.

## Ownership
Owns user interface components, service worker caching, PWA installation manifests, and frontend theme switching.

## Local Contracts
- Web themes default to the Busnes.app cream/light and charcoal/dark palettes with orange accents, following the OS until a browser-local choice is saved. Preserve existing named themes and saved choices.
- Sign-out resets the shell (user, workspaces, selection, tab, settings, new-tab preference) only after the server confirms; a failed or unreachable logout keeps the session and shows an error.
- A signed-in user with `must_change_password` sees only password replacement and sign-out. Replacement uses `secureFetch`, returns to login after session revocation, and never exposes the normal navigation before completion.
- Strict TypeScript type safety without unused imports.
- The authenticated shell uses a persistent sidebar; the selected page is marked by a quiet surface and slim accent rail, with a horizontal overflow navigation on small screens.
- Dynamic theme selection applies `data-theme` attribute to the root HTML document and persists to `localStorage`.
- Authenticated state-changing requests use `secureFetch` so the CSRF cookie (`__Host-ky_csrf` on HTTPS host-only deployments, else `ky_csrf`) is mirrored into `X-CSRF-Token`; the editor bootstrap script reads it the same way. Login and MFA posts send `Content-Type: application/json`.
- A PoW solution buys one login attempt; `Login.tsx` remounts `CaptchaWidget` after every attempt.
- Register the service worker from the production JS bundle; keep `script-src 'self'` intact.
- Worker caching is limited to the same-origin public shell, manifest and assets. HTML is network-first with offline fallback so deployments refresh; dynamic/auth routes stay uncached. `vite.config.ts` stamps a build id (hash of the output file names) into `dist/sw.js` as the cache name, so `activate` evicts the previous deploy's hashed assets; the build fails if `public/sw.js` loses its single `__BUILD_ID__` placeholder.
- The Account page also lists app passwords (`src/pages/AppPasswords.tsx`): create by device name, show the server URL, username and password once, list name, created and last use, revoke after `window.confirm`.
- Every signed-in user has an Account page (`src/pages/TwoFactor.tsx`). Local accounts turn TOTP on (setup key plus an `otpauth://` link, no QR renderer or dependency), confirm with a code and see the recovery codes once with a save warning; turning it off takes the password and a TOTP or recovery code. Directory accounts are told their identity provider manages MFA.
- KyDrive deployments use SQLite; inherited recovery UI still reports snapshot preconditions. The Recovery screen warns when `key_in_data_dir` is set.
- The suite SSO button reads `Sign On with KyIdentity`; the login description identifies organization files and shared workspaces.

- My files and Shared workspaces live in the main application sidebar, with no redundant Files destination. The selected workspace names the page. Personal workspace creation is an idempotent authenticated POST before listing. New file offers document/spreadsheet/presentation/markdown/rtf/whiteboard creation with a native name dialog, then opens the created file in Euro-Office (for Office/PDF/Markdown/RTF) or the Excalidraw whiteboard (for `.excalidraw`). Choosing a type closes the New file menu.
- "Open files in a new tab" (sidebar, every signed-in user) is a per-account server preference, default on, read from `/api/auth/me` and saved with `PUT /api/auth/preferences`; a failed save reverts the checkbox. On, file links and Create & open use a new tab (the tab is opened inside the click so pop-up blockers allow it, then pointed at the editor; a blocked tab falls back to in-place). Off, files open in the drive tab. The browser suite stays under the server's 20 sign-ins per minute. The drive opens on files with a compact upload/folder toolbar and per-row action menus. Folders are rows in the file list and a breadcrumb shows and navigates the current path (`src/pages/drive/client.ts` wraps the API). Workspace settings contain group permissions and quotas; they do not crowd the file list.
- Uploads use resumable sessions (`src/pages/drive/upload.ts`): 32 MiB `Content-Range` chunks, progress from bytes the server acknowledged, resume from the server's count after a dropped chunk (3 retries with backoff, then Retry resumes the kept session); a refused upload cancels its session. Upload files (multi-select), Upload folder (`webkitdirectory`) and dropping files or folders on the file list share one queue (`Uploads.tsx`) that uploads one file at a time and reloads once it drains. Dropped folders are created parents first, reusing a live folder of the same name; a taken file name fails that file, never overwrites.
- A search box above the drive (`Search.tsx`) queries `/api/drive/search` after 2 characters and a 300 ms pause, lists name, workspace and path, says when results are capped, and opens the result's folder (switching workspace first when needed). Every folder row's menu, readers included, has Download zip.
- Guest links: `/g/#<token>` renders `GuestPage` from `main.tsx` with no app chrome and no sign-in. It asks for a password on 401, lists the shared folder from its root down, downloads through a hidden POST form (so the browser saves natively and the token stays in the body) and, upload-only, sends files with the token in a header. The admin Settings page has `GuestLinkSettings` (off by default, longest lifetime); the Share dialog shows a guest-link section only while the policy is on.
- `ShareDialog` shares a file or folder with people (found through `/api/drive/people`) or, for workspace managers, groups, at reader or editor (manager for managers), and lists and removes shares. It also creates organisation links (reader or editor, expiry 1/7/30 days or never), shows the URL once and lists and revokes links. `/l/#<token>` is handled by `src/pages/drive/links.ts`: the token moves to session storage and out of the address bar before anything loads, and is opened after sign-in (a file opens its editor, a folder goes to Shared with me; an unusable link shows one generic message). File and folder menus show Share to managers, and to editors when the workspace allows editors to share (a manager-only toggle in Workspace settings). `SharedView` (sidebar Shared with me, selection `SHARED_WITH_ME`) lists items shared outside the user's workspaces and browses into shared folders from the shared root down.
- `QuickLook` (`src/pages/drive/QuickLook.tsx`) previews a file in a dialog: a `HEAD` on `/api/drive/files/{id}/preview` gives the server-sniffed type (415 shows "No preview" with Download), then an `<img>`, a PDF `<iframe>`, `<audio>`/`<video>`, or the first 256 KiB of text fetched with `Range` into a `<pre>` (never as markup). A file's name opens its editor when `opensInEditor` (Office formats, Markdown, RTF, TXT, CSV, `.excalidraw`) and quick look otherwise, PDFs included; every live file's menu has Preview, and Open editor when `hasEditor` (those formats plus PDF). The drive list and Shared with me both route this way.
- `MoveDialog` renames, moves and copies files and folders. It offers other workspaces for a file move only when the source role is manager (the server also requires it); copy lists every workspace the user can edit; folder moves stay in their workspace. It ignores stale folder lists from a previous target.
- The trash view lists trashed files and folders. Restore is open to editors; Delete permanently, Empty trash and Delete version are manager-only (personal owner counts) and each asks `window.confirm`. Administrators get a Retention form (`trash_days`, `keep_versions`) on shared workspaces only; trash 0 follows the drive-wide setting, versions 0 keeps all. The admin Settings page has a drive-wide Trash form (`TrashRetention`, `/api/drive/trash-retention`, default 90, 0 = keep) whose copy says trashed items are permanently deleted after N days.
- Administrators get a Leavers panel (`src/pages/drive/Leavers.tsx`): each leaver's label, status, size and item count, never file names; a destination picker of shared workspaces and colleagues; `window.confirm` naming the size and destination before the handover POST.
- `/whiteboard.html` is a second Vite entry (`src/whiteboard/`) running upstream `@excalidraw/excalidraw` under the global CSP. It opens files through Excalidraw's own loader and autosaves `serializeAsJSON(..., 'local')` through the uploads API with the expected revision; opening never writes, and any rejected save (conflict, quota, access) stops autosave. No collaboration, share links or library persistence.
- Excalidraw is pinned exactly and bumped by Dependabot in its own group; `package.json` overrides (ranges) patch its vulnerable transitive deps until upstream ships fixes. `vite.config.ts` rewrites its esm.sh font fallback to `/excalidraw/`, failing the build if that string moves, and copies canvas fonts into `dist/excalidraw/fonts`. Xiaolai (CJK, 13 MB) goes to `dist-fonts/` instead of the embedded bundle; the image ships it at `KY_EXCALIDRAW_FONTS_DIR`.
- KyDrive owns files, folders, versions/trash, workspace permissions/quotas and operational status/audit. People/group management links to KyIdentity; no separate local directory editor.
- Hide privileged navigation from staff. Directory-managed group membership and workspace access are distinct. Managers can configure group grants; only administrators set quota or see global operations.

## Verification
- Browser setup: build the frontend, run `go build -o .browser/server ./cmd/server` at the repo root, then `cd web && npx playwright install chromium && npm run test:browser`. CI also installs browser OS dependencies.
- `make test-web` or `cd web && npm ci && npm test`, then `npm run build` (vitest with jsdom; `src/pages/Backup.test.tsx` renders the recovery screen against a stubbed status route and saves the Document retention form; `src/pages/drive/client.test.ts` and `MoveDialog.test.tsx` cover the file-management client and dialog; `Leavers.test.tsx` the handover panel; `TwoFactor.test.tsx` MFA enrol/confirm/disable; `Settings.test.tsx` the drive-wide trash form; `src/App.test.tsx` sign-out). `web/dist` and `dist-fonts/` are build output, not committed; the build restores `dist/.gitkeep` so `go:embed` compiles on a fresh clone.

## Shared browser UI

- `src/ky-ui/` is generated from Busnes-app/ky-ui, pinned by `VERSION` file hashes. Change shared colors, navigation states and storage helpers upstream, then run its consumer sync with an explicit worktree map; do not hand-edit vendored files.
- Products own layout, routes, saved choice keys and named palettes. Busnes aliases consume shared tokens; mark primary navigation with `ky-nav-item` while preserving current-page semantics.
- Verify vendored files with `node src/ky-ui/check-vendor.mjs` from this document's directory. Builds/CI run that check. Rendered evidence and capture limitations are recorded in the repository-root `UI-VERIFICATION.md`.\n
