# Web

## Purpose
React 19 + TypeScript + Vite PWA frontend embedding the ky-ui suite theme catalog (Busnes light/dark defaults, the shipped `patina`, `cyber`, `nord`, `paper`, `oled` and the other suite palettes), client-side WebCrypto PoW CAPTCHA, and administrative management panels.

## Ownership
Owns user interface components, service worker caching, PWA installation manifests, and frontend theme switching.

## Local Contracts
- Newly added suite palettes tint error/success text toward their ink for readable status text on light and dark surfaces; the five shipped base palettes retain their original status values. Browser regressions measure all six new light palettes against both page and panel surfaces. The filled `.btn-danger` takes the page colour (`--bg`) as its label under the same 15 suite palettes, because the tint makes the fill too dark for a dark `--button-text`. Busnes and the five base palettes keep `--button-text`. `browser/danger-button.spec.mjs` measures the rendered label in the real "Delete permanently" confirmation at rest, hover and focus.
- Web themes default to the Busnes.app cream/light and charcoal/dark palettes with orange accents, following the OS until a browser-local choice is saved. Preserve existing named themes and saved choices.
- Sign-out resets the shell (user, workspaces, selection, tab, settings, new-tab preference) only after the server confirms; a failed or unreachable logout keeps the session and shows an error.
- A signed-in user with `must_change_password` sees only password replacement and sign-out. Replacement uses `secureFetch`, returns to login after session revocation, and never exposes the normal navigation before completion.
- Strict TypeScript type safety without unused imports.
- The authenticated shell uses a persistent sidebar; the selected page is marked by a quiet surface and slim accent rail. Below 720 px the brand and sign-out share the top row, both navigations (wrapped in `.app-navs`, `display: contents` on desktop) scroll as one row that `AppHeader` scrolls to keep the current destination in view without moving the page, and the new-tab preference sits under it. Evidence: `docs/ui-visual-refinement-2026-10-26/`.
- The sidebar footer (`© <year> · MIT License`, `AppHeader`) opens the About dialog: app name, the server version from the signed-in `/api/auth/me` `version` field, and `src/mit.txt`, a copy of the root `LICENSE.txt` (`TestWebLicenceMatchesRepo` in `internal/api`; the web build sees only `web/`). `browser/launch-fixes.spec.mjs` checks it against the real server.
- Theme selection applies the catalog ID as `data-theme` on the root element and persists it under `ky_theme`. Every signed-in user has an Appearance page (primary navigation) with Match system and every catalog theme as the shared native radio cards (`ky-appearance`); the shell (sidebar, phone header) has no theme selector, by owner decision; only the login page keeps a compact dropdown over the same saved choice; the administrator Settings page's System card opens Appearance (Open Appearance) instead. The five themes KyDrive shipped before the catalog keep their exact `styles/theme.css` values (no inline palette); the other named themes are applied inline by `applyThemeVariables`. Their Appearance previews carry the theme's own `data-theme`, so those blocks colour the card (sidebar = `--panel`, as `.app-header` renders them); the unit and browser tests compare each preview with the applied palette.
- Authenticated state-changing requests use `secureFetch` so the CSRF cookie (`__Host-ky_csrf` on HTTPS host-only deployments, else `ky_csrf`) is mirrored into `X-CSRF-Token`; the editor bootstrap script reads it the same way. Login and MFA posts send `Content-Type: application/json`.
- A PoW solution buys one login attempt; `Login.tsx` remounts `CaptchaWidget` after every attempt.
- Register the service worker from the production JS bundle; keep `script-src 'self'` intact.
- Worker caching is limited to the same-origin public shell, manifest and assets. HTML is network-first with offline fallback so deployments refresh; dynamic/auth routes stay uncached. `vite.config.ts` stamps a build id (hash of the output file names) into `dist/sw.js` as the cache name, so `activate` evicts the previous deploy's hashed assets; the build fails if `public/sw.js` loses its single `__BUILD_ID__` placeholder.
- The Account page also lists app passwords (`src/pages/AppPasswords.tsx`): create by device name, show the server URL, username and password once, list name, created and last use, revoke after a styled confirmation (`useConfirm`). Kind *AI agent* creates an agent token instead: *Read only* (default) or *Read and write* (with the write warning), an optional *Limit to folder* path; the token is shown once with OpenClaw and Hermes Agent config reading `KYDRIVE_TOKEN` and the skill install commands. Every issuing screen names who gets the credential and its level (`grant`: the form before creating, the one-time reveal, the widening confirm); never a generic "an app wants access" prompt. Agent rows show an access select (widening to write asks `window.confirm`), the folder limit or that it is gone, and the 90-day revocation date.
- Linked computers: `/link?redirect=&challenge=&state=&name=&platform=` (opened by the desktop app) is handled by `src/pages/LinkDevice.tsx`. The query moves to session storage and out of the address bar at once, so it survives sign-in, KyIdentity included; once signed in (and past any password replacement) the app shows only the approval screen: name, platform, request IP (`/healthz` `clientIp`) and time. Nothing posts on load. A request failing the server's rules (loopback-only redirect, S256 challenge, state, name, platform) shows an error and no button; Approve posts `/api/devices/approve` once and navigates only to a redirect that starts with the requested one; Cancel and Approve clear the stored request. The Account page lists computers (`src/pages/Devices.tsx`: name, platform, linked, last used) with a Revoke dialog: "Also remove KyDrive files from this computer", defaulting to the policy and disabled when locked, plus the offline and no-guarantee caveats; it sends `DELETE /api/devices/{id}?wipe=`. The admin Settings page has `DevicePolicySettings` (Computers: wipe default and lock, `/api/drive/device-policy`).
- Account aligns with the other pages at the left gutter; credential creation and dialog completion are secondary actions, and disabled Account buttons use neutral theme tokens.
- Every signed-in user has an Account page (`src/pages/TwoFactor.tsx`). Local accounts turn TOTP on (setup key plus an `otpauth://` link, no QR renderer or dependency), confirm with a code and see the recovery codes once with a save warning; turning it off takes the password and a TOTP or recovery code. Directory accounts are told their identity provider manages MFA.
- KyDrive deployments use SQLite; inherited recovery UI still reports snapshot preconditions. The Recovery screen warns when `key_in_data_dir` is set.
- The suite SSO button reads `Continue with Single Sign On`, below a bare divider line (no repeated heading); the login description identifies organization files and shared workspaces.

- My files and Shared workspaces live in the main application sidebar, with no redundant Files destination. The selected workspace names the page. Personal workspace creation is an idempotent authenticated POST before listing. New file offers document/spreadsheet/presentation/markdown/rtf/whiteboard creation with a native name dialog, then opens the created file in Euro-Office (for Office/PDF/Markdown/RTF) or the Excalidraw whiteboard (for `.excalidraw`). The toolbar's New menu holds New folder, the document types and Upload folder; Upload files is the primary page-header action. Folder and Trash headings identify the current location; root and nested breadcrumbs remain available. Administrators find Operations & audit, Create shared workspace and Leavers inside one initially collapsed Administration disclosure after the file task; existing administrator guards remain unchanged.
- "Open files in a new tab" (Account → Files, every signed-in user) is a per-account server preference, default on, read from `/api/auth/me` and saved with `PUT /api/auth/preferences`; a failed save reverts the checkbox. On, file links and Create & open use a new tab (the tab is opened inside the click so pop-up blockers allow it, then pointed at the editor; a blocked tab falls back to in-place). Off, files open in the drive tab. The browser suite stays under the server's 20 sign-ins per minute. The drive opens on files with a compact upload/folder toolbar and per-row action menus. Folders are rows in the file list and a breadcrumb shows and navigates the current path (`src/pages/drive/client.ts` wraps the API). Workspace settings contain group permissions and quotas; they do not crowd the file list. Administrators also get a Workspace panel there (`src/pages/drive/WorkspaceAdmin.tsx`, shared workspaces only): Rename (a 409 says the name is taken) and Delete workspace, which asks the styled danger confirmation naming what stops working, then clears the selection so the drive reopens My files; a 409 says only an empty workspace can be deleted.
- Uploads use resumable sessions (`src/pages/drive/upload.ts`): 32 MiB `Content-Range` chunks, progress from bytes the server acknowledged, resume from the server's count after a dropped chunk (3 retries with backoff, then Retry resumes the kept session); a refused upload cancels its session. Upload files (multi-select), Upload folder (`webkitdirectory`) and dropping files or folders on the file list share one queue (`Uploads.tsx`) that uploads one file at a time and reloads once it drains. Dropped folders are created parents first, reusing a live folder of the same name. Before uploading, names already taken in their folder (from a fresh file listing) are put to the user once per batch: *Replace (new version)* starts the session with `file` and the current `revision`, *Keep both* uploads under the first free `name (n).ext` (the server's guest-upload numbering), *Cancel* skips those files only. A 409 at session start (taken meanwhile) shows the same three choices on that row instead of the server message; nothing ever overwrites without a choice.
- A search box above the drive (`Search.tsx`) opens its results below it (Escape or a click elsewhere hides them) and queries `/api/drive/search` after 2 characters and a 300 ms pause, lists name, workspace and path, marks the query in a name match's name (case-insensitive, as text), shows a content match's snippet as text with `<mark>` around its UTF-16 highlight ranges (never markup; bad ranges skipped, a malformed snippet refuses the response), says when results are capped, when some of the user's files are still being indexed and that contents match whole words, and opens the result's folder (switching workspace first when needed). Every folder row's menu, readers included, has Download zip.
- Guest links: `/g/#<token>` renders `GuestPage` from `main.tsx` with no app chrome and no sign-in. It asks for a password on 401, lists the shared folder from its root down, downloads through a hidden POST form (so the browser saves natively and the token stays in the body) and, upload-only, sends files with the token in a header. The admin Settings page has `GuestLinkSettings` (off by default, longest lifetime); the Share dialog shows a guest-link section only while the policy is on.
- Native dialog close controls keep a fixed non-shrinking40px square alongside long titles. QuickLook keeps Close beside the title at both widths, with40px header controls and a flat text preview while preserving the bounded viewer for every media kind.
- `ShareDialog` explains the existing search-and-Add action through help immediately below the person field, before Access on phone; it shares a file or folder with people (found through `/api/drive/people`) or, for workspace managers, groups, at reader or editor (manager for managers), and lists and removes shares. It also creates organisation links (reader or editor, expiry 1/7/30 days or never), shows the URL once and lists and revokes links. `/l/#<token>` is handled by `src/pages/drive/links.ts`: the token moves to session storage and out of the address bar before anything loads, and is opened after sign-in (a file opens its editor, a folder goes to Shared with me; an unusable link shows one generic message). File and folder menus show Share to managers, and to editors when the workspace allows editors to share (a manager-only toggle in Workspace settings). `SharedView` (sidebar Shared with me, selection `SHARED_WITH_ME`) lists items shared outside the user's workspaces and browses into shared folders from the shared root down.
- `QuickLook` (`src/pages/drive/QuickLook.tsx`) previews a file in a dialog: a `HEAD` on `/api/drive/files/{id}/preview` gives the server-sniffed type (415 shows "No preview" with Download), then an `<img>`, a PDF `<iframe>`, `<audio>`/`<video>`, or the first 256 KiB of text fetched with `Range` into a `<pre>` (never as markup). A file's name opens its editor when `opensInEditor` (Office formats, Markdown, RTF, TXT, CSV, `.excalidraw`) and quick look otherwise, PDFs included; every live file's menu has Preview, and Open editor when `hasEditor` (those formats plus PDF). The drive list and Shared with me both route this way. `FileIcon` shows a lucide type icon per extension (folders get a folder icon), and for PNG, JPEG, GIF and WebP a lazy `<img>` of `/api/drive/files/{id}/thumbnail?r=<revision>` that falls back to the icon when the server refuses. Documents and PDFs keep their type icon in the list: a 32 px render of a page reads as a blank tile. The server's Office/PDF thumbnail route is unchanged.
- `MoveDialog` renames, moves and copies files and folders. It offers other workspaces for a file move only when the source role is manager (the server also requires it); copy lists every workspace the user can edit; folder moves stay in their workspace. It ignores stale folder lists from a previous target.
- The trash view lists trashed files and folders. Restore is open to editors; Delete permanently, Empty trash and Delete version are manager-only (personal owner counts) and each asks a styled confirmation naming what is lost, with the action styled as danger. Administrators get a Retention form (`trash_days`, `keep_versions`) on shared workspaces only; trash 0 follows the drive-wide setting, versions 0 keeps all. The admin Settings page has a drive-wide Trash form (`TrashRetention`, `/api/drive/trash-retention`, default 90, 0 = keep) whose copy says trashed items are permanently deleted after N days.
- Administrators get a Leavers panel (`src/pages/drive/Leavers.tsx`): each leaver's label, status, size and item count, never file names; a destination picker of shared workspaces and colleagues; a styled confirmation naming the size and destination before the handover POST.
- `/whiteboard.html` is a second Vite entry (`src/whiteboard/`) running upstream `@excalidraw/excalidraw` under the global CSP. It opens files through Excalidraw's own loader and autosaves `serializeAsJSON(..., 'local')` through the uploads API with the expected revision; opening never writes, and any rejected save (conflict, quota, access) stops autosave. No collaboration, share links or library persistence.
- Excalidraw is pinned exactly and bumped by Dependabot in its own group; `package.json` overrides (ranges) patch its vulnerable transitive deps until upstream ships fixes. `vite.config.ts` rewrites its esm.sh font fallback to `/excalidraw/`, failing the build if that string moves, and copies canvas fonts into `dist/excalidraw/fonts`. Xiaolai (CJK, 13 MB) goes to `dist-fonts/` instead of the embedded bundle; the image ships it at `KY_EXCALIDRAW_FONTS_DIR`.
- Inputs/selects, secondary button outlines and icon-button outlines consume shared `--ky-field-border`, preserving each palette’s ink/background derivation. Icon buttons use the shared40px control size; quiet dividers remain separate.
- Components follow the Ky Suite house style (KyIdentity forms, tables, dialogs, buttons) on the ky-ui tokens; `src/styles/theme.css` owns them. Pages use `.page` (`.page-narrow` for Account) with a `.page-header`; cards are `.panel`; forms `.form`/`.form-row`/`.field` with constrained widths and radio groups as `.choice` cards. Buttons: the bare `button` is primary (one per view), `.btn-secondary`, `.btn-ghost`, `.btn-danger` (confirming a destructive action) and `.btn-danger-quiet` (a destructive row action). Every modal is `components/Dialog.tsx` (titled header with Close, body, footer of secondary then primary actions; Escape closes); confirmations use its `useConfirm`, never `window.confirm`. Row actions are `components/Menu.tsx`: `role="menu"` items that close the menu after any choice, on Escape (focus back on the button) and on an outside click. Server times render through `components/When.tsx`: local date and time plus a relative phrase, the exact instant in `<time dateTime>`; never raw RFC 3339. Visible `:focus-visible` everywhere; `prefers-reduced-motion` turns transitions off. Below 720 px the file table drops its Size and Version columns into a meta line under the name.
- Version history is a dialog listing versions newest first with the current one marked; Restore (editors) saves an older version as a new one and Delete (managers) removes an old one after confirmation. The trash view has a Trash heading with its retention and Empty trash.
- KyDrive owns files, folders, versions/trash, workspace permissions/quotas and operational status/audit. People/group management links to KyIdentity; no separate local directory editor.
- Hide privileged navigation from staff. Directory-managed group membership and workspace access are distinct. Managers can configure group grants; only administrators set quota or see global operations.

- Phone headers retain signed-in name/role beside sign-out and a plain scroll hint for the single navigation row. Selection and keyboard focus reveal the destination plus its4px outer focus-ring margin by scrolling only that row. Account owns the file-opening preference; moving it never changes its per-account persistence or failed-save rollback. Drive search spans the content width; Upload aligns to the page heading. Trash restoration/deletion actions use40px controls with Back to files before Empty trash.

## Verification
- Completed uploads have a compact receipt; keep every finished item and failed/retry row until the existing explicit Clear finished action removes completed rows.
- Browser setup: build the frontend, run `go build -o .browser/server ./cmd/server` at the repo root, then `cd web && npx playwright install chromium && npm run test:browser`. CI also installs browser OS dependencies.
- `make test-web` or `cd web && npm ci && npm test`, then `npm run build` (vitest with jsdom; `src/pages/Backup.test.tsx` renders the recovery screen against a stubbed status route and saves the Document retention form; `src/pages/drive/Search.test.tsx` the search box and snippets; `src/pages/drive/client.test.ts` and `MoveDialog.test.tsx` cover the file-management client and dialog; `Leavers.test.tsx` the handover panel; `WorkspaceAdmin.test.tsx` workspace rename, the delete confirmation and both 409 messages; `TwoFactor.test.tsx` MFA enrol/confirm/disable; `Settings.test.tsx` the drive-wide trash form; `LinkDevice.test.tsx` the link approval (one post, never on load, no redirect for a bad request); `Devices.test.tsx` the computers list, the revoke wipe flag, the locked checkbox and the policy form; `AppPasswords.test.tsx` the WebDAV password and AI agent token flows, the write warning and the confirmed access change; `Uploads.test.tsx` the queue and the Replace/Keep both/Cancel choice; `src/components/components.test.tsx` the menu closing, the confirmation dialog, date formatting, version history and document icons; `src/App.test.tsx` sign-out). `web/dist` and `dist-fonts/` are build output, not committed; the build restores `dist/.gitkeep` so `go:embed` compiles on a fresh clone.

## Shared browser UI

- `src/ky-ui/` is generated from Busnes-app/ky-ui, pinned by `VERSION` file hashes. Change shared colors, navigation states and storage helpers upstream, then run its consumer sync with an explicit worktree map; do not hand-edit vendored files.
- Products own layout, routes, saved choice keys and named palettes. Busnes aliases consume shared tokens; mark primary navigation with `ky-nav-item` while preserving current-page semantics.
- Verify vendored files with `node src/ky-ui/check-vendor.mjs` from this document's directory. Builds/CI run that check. Rendered evidence and capture limitations are recorded in the repository-root `UI-VERIFICATION.md`.\n
