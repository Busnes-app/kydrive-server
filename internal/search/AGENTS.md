# Content search index

## Purpose
Own the content search index: the tokenizer, the query syntax, the blind index database, the sealed prefix vocabulary and the snippet maker. File text reaches this package only in memory; nothing it writes holds a word, a name, a file type or a blob ID.

## Ownership
Owns `<KY_DATA_DIR>/search/index.db` (schema, keys, queue, postings, scoring), `<KY_DATA_DIR>/search/vocab` and the text-to-token rules. Where text comes from (extraction, PDF conversion, the sealed text cache), the worker, permissions and HTTP/MCP shapes belong to `internal/api` (`search_index.go`); which files a user may search belongs to `internal/drive` (`SearchContent`).

## Local Contracts
- The index is its own SQLite file with its own connection (WAL, `synchronous=NORMAL`, `secure_delete=ON`), never the main database: the capsule caps one member at 64 MiB and the main pool has one connection. It is in no backup and can always be rebuilt; `Open` deletes and restarts an index built under another deployment key or `TokenizerVersion` (`meta.check`).
- Keys are `crypto.DeriveKey` subkeys of the deployment key: `kydrive:search-token` (term HMAC, first 8 bytes as a signed integer), `kydrive:search-doc` (`Ref` = HMAC of `blob:kind`, 16 bytes), `kydrive:search-check` (fingerprint), `kydrive:search-vocab` (vocabulary seal). Term hashes are deterministic: equal words share a token across the drive, so frequency and co-occurrence patterns leak to whoever reads the file, words do not. Document rows carry no blob ID or kind, only `Ref`.
- Tables: `docs(ref, state 1 done / 2 failed, len, err code, attempts, updated)`, `postings(token, doc, tf) WITHOUT ROWID` (no index by document: `Keep` deletes in batched scans), `queue(file, first, not_before)` holding random file IDs until processed, `meta` (`check`, `cursor` = last drive change seq queued). `Put` and `Fail` drop the file's queue row in their transaction, so a crash repeats work and never loses it. A requeued file waits for its latest debounce but at most 60 s after it was first queued.
- Tokens (`scan`): per rune NFKD, combining marks dropped, lower case, `ß`→`ss`, final sigma→sigma; CJK (Han, Hiragana, Katakana, Hangul) runes are left as they are and index as overlapping bigrams (a lone one as itself); other tokens are runs of letters and digits, 2 runes to 64 bytes. No stemming, no stop words. A document keeps its first `MaxDocTerms` (50 000) distinct terms, frequencies capped at 255; a query its first `MaxQueryTerms` (8). Change any rule: bump `TokenizerVersion`.
- `ParseQuery` (`query.go`): a token directly followed by `*` with `MinPrefixRunes` (3) or more runes, not CJK, is a prefix; a closed double-quoted run of 2+ tokens is a phrase (one token: a word; unclosed quotes: words; no prefixes inside); the rest are words. At most `MaxQueryTerms` distinct terms (a prefix `t*` and the word `t` are two); a phrase that does not fit is dropped whole.
- `Match(ctx, Query, refs)` is AND of groups scored BM25 (k1 1.2, b 0.75) with N, document frequency and average length over the refs it is given only, so documents the caller cannot read never match nor shape the order: each word and each phrase term is a group of one; each prefix is a group of its vocabulary expansions (tf summed), none of which is empty or the match is. `Matched.Pending` counts given refs not yet settled (done, or failed `MaxAttempts` times); `Expanded` and `Capped` report the expansions. Phrase order is the caller's to check (`HasPhrases`, consecutive tokens, so breaks, punctuation and one-letter words between do not count).
- Vocabulary (`vocab.go`): distinct indexed words of 3+ runes, not CJK, each with an approximate document count, drive-wide, in memory; `Put` and `Learn` add to it, nothing removes from it but a rebuild. `expand` returns at most `MaxPrefixWords` (100) words, most documents first. It is sealed to `vocab` (`crypto.EncryptAESGCMAAD`, AAD = `kydrive:search-vocab:` + the index check, so another key or `TokenizerVersion` opens it empty) by `SaveVocab` (when changed, at most once a minute, or now) and `Close`, written to a temporary file in the directory, synced and renamed. Its plaintext holds `stamp` (documents updated before it are in it) and `built` (last full build). `VocabDue` asks for a full build when none was done or the last is `vocabDay` (24 h) old, else for documents updated at or after `stamp`; `BuildVocab`/`Add`/`Done` replace or extend it and seal it. A missing, damaged or foreign file is empty until the worker rebuilds it; no reindex is ever needed. Words of every user's files are in it: a capped prefix's choice depends on the whole drive (documented in `docs/RECOVERY-AND-ENCRYPTION.md`).
- `MakeSnippet(r, terms, phrases)` reads at most 4 MiB of text, counts a phrase only where it occurs whole (one hit from its first term to its last), picks the first window with the most distinct terms, collapses white space and control characters, and returns `[start,end)` highlight offsets in UTF-16 code units of its text, overlapping ones merged. It is plain text, never markup.

## Verification
- `go test -race ./internal/search` (folding, CJK, caps, UTF-16 highlights, BM25 scope, queue debounce, key change rebuild, no plaintext in `index.db` or its WAL; `query_test.go`: query syntax, phrases across breaks, phrase snippets, prefix scope and cap, the vocabulary sealed, tampered, truncated, foreign key or tokenizer, builds and garbage); `go test -fuzz=FuzzSnippet ./internal/search` for highlight ranges.
