# Drive domain

## Purpose

Own personal and organization workspaces, files, folders, immutable versions and group access grants.

## Ownership

Own drive schema and domain operations over the application's database and blob directory. Identity rows remain owned by the inherited identity stores.

## Local Contracts

- Shared documents belong to workspaces, independent of user deletion.
- Shared workspace names are unique ignoring ASCII case (`CreateWorkspace` and `RenameWorkspace` return `ErrConflict` through `nameFree`; `TestSharedWorkspaceNamesAreUnique`, `TestRenameWorkspace`); every My files is named "My files" and is exempt, and no shared workspace may take that name, in any case (`ErrConflict`), since WebDAV, MCP and agent folder limits call each user's own `/My files`.
- `workspaces.go`: `RenameWorkspace` (admin, shared only, `ErrDenied` for My files or a deleted workspace; event `workspace.renamed`, resource `<id> from="old" to="new"`). `nameFree` counts deleted workspaces until purge (message `workspace name exists in Deleted workspaces`), so a restore never collides. `DeleteWorkspace(user, id, confirm)` (admin, shared only, My files `ErrDenied`; unknown or already deleted: nil and no event) returns whether it was recoverable. An empty workspace (no live or trashed file or folder) is removed in one transaction: it refuses (`ErrConflict`) an upload session that is unexpired or claimed for completion, then `removeWorkspace` deletes upload sessions, links and their opener rows, shares, grants, agent tokens rooted in it, its change rows and floor and the workspace row and marks its service tokens revoked. A workspace holding items needs `confirm` equal to its exact name (else `ErrConflict` `not empty; confirm with its name`); one transaction revokes its links, service tokens, rooted agent tokens and editor sessions (documents closed, `editor_epoch` bumped) and sets `deleted_at` (RFC 3339) and `deleted_by` (schema 18). Grants, shares, items and the change log stay. Both write `workspace.deleted` with `<id> name="..."` (plus `recoverable=true files=N folders=N` when recoverable) and each revoked kind's count. Retention (`ApplyRetention`) skips a deleted workspace, so its trash and versions stay exactly as deleted until restore or purge (`TestRetentionSparesDeletedWorkspaces`). A deleted workspace grants no rank (`access.go`), leaves `Workspaces` (admin listing too) and `SharedWithMe`, and `sharedWorkspace` refuses it, so configuration, grants, handover into it, WebDAV (404) and the change feed and snapshot (403, on which the desktop client evicts) all stop. `RestoreWorkspace` (admin; not deleted, personal or unknown: `ErrNotFound`) clears it, event `workspace.restored`. `DeletedWorkspaces` (admin) lists name, deleter, size and item count, never file names. `PurgeDeletedWorkspaces(at, days)` (retention worker, actor `system`, 0 = never) removes each workspace deleted more than `days` ago in its own transaction: editor rows, versions, files, folders, then `removeWorkspace`; it skips one whose files have an editor session with `drop_done=false`, and returns the blobs `unreferenced` found for removal after commit (shared blobs stay; the orphan sweep and the search index's `Keep` clear the rest). Event `workspace.purged` with counts. `TestDeleteWorkspace`, `TestDeleteWorkspaceRacesUploads`, `TestRecoverableDeleteWorkspace`, `TestPurgeDeletedWorkspaces`, `TestPurgeDeletedWorkspaceWaitsForEditorDrop`.
- Personal workspaces are unique per immutable account ID, default to 10GiB, and allow only the active owner; an admin handover may move a leaver's tree into a shared workspace or a colleague's My files, without granting the admin read access. Group grants and shared-directory management are rejected for personal workspaces, including administrator grants. Retain ownership/data after offboarding until an admin handover; session revocation covers both personal and shared files.
- Read current user status and group memberships when authorizing each operation. Global admin can manage workspace configuration; shared content requires an explicit group grant and personal content requires the active owner.
- Blob encryption (`sealed.go`): `WriteBlob` always seals as KYB2: `KYB2` || an age v1 file (`filippo.io/age`, STREAM ChaCha20-Poly1305, 64 KiB chunks, random file key, last-chunk flag, header MAC). Its one `kydrive` stanza wraps the file key with AES-256-GCM (zero nonce) under `HKDF-SHA256(deployment key, random 16-byte stanza salt, binding)`; the binding is `kydrive:kyb2:blob:<blob ID>` (the file's own name), or `kydrive:kyb2:cache:<blob ID>` for thumbnail/text cache entries, so a blob moved to another ID, or a cache entry moved into the blob root, does not open. Binding is to the blob ID, not the file ID, because `CopyFile` and `RestoreVersion` share blobs. KYB1 (`KYB1` || 32-byte salt, AES-256-GCM 64 KiB chunks under `HKDF-SHA256(deployment key, salt, "kydrive:blob")`, nonce = 11-byte chunk index || final flag, header as AAD, not bound to an ID) is read only, until `UpgradeBlobs` has rewritten it; `OpenBlob` dispatches on the magic. Tink Go's streaming AEAD was rejected: it has no random-access reader, and downloads, MCP reads and zip text extraction seek. `SealedSize` is the exact KYB2 size; `StoredSizeOK` also accepts KYB1. `OpenBlob` requires the exact size for the format, authenticates the last chunk on open and each chunk before returning any of its bytes. `drive_versions.sealed` travels with the blob ID on copy and restore; `digest` and `size` describe plaintext.
- `UpgradeBlobs` (`upgrade.go`, from `RunBlobSealing`, `blobUpgradeRate` 32 MiB/s) rewrites each blob in `drive_blob_kyb1` (filled by schema 16 with every `sealed=1` blob; nothing else adds to it) in place: stage a KYB2 copy bound to the same ID (`.upload-*`, fsynced), decrypt it against the version digest, then in one transaction re-check a version still names the blob, rename over it, fsync the directory and delete the queue row. A purge is never undone; a crash at any step leaves a readable blob and the rerun repeats at most one rewrite; leftover staging files are `SweepOrphans`'. A blob that fails stays queued and is logged. Logs `blob format: ...`; `rewrote N KYB1 blobs as KYB2; none remain` and an empty `drive_blob_kyb1` mean KYB1 reading can go (cache entries may still be KYB1 and must then read as misses).
- Name encryption (`names.go`): `drive_files.name` and `drive_folders.name` hold `crypto.EncryptAESGCMAAD(name, HKDF-SHA256(deployment key, "kydrive:name"), "<table>:<row id>")`, so a name cannot be moved to another row. `name_hmac` = hex HMAC-SHA256(HKDF-SHA256(deployment key, "kydrive:name-hmac"), name); the live-name unique indexes `drive_live_names`/`drive_live_folders` are `(workspace,parent,name_hmac) WHERE trashed=false`, keeping exact case-sensitive uniqueness while restore and moves change only `parent`/`workspace`. Equal names share an HMAC across the database (equality leaks, content does not). Every write that sets a name (`AddFolder`, `publishTX`, `MoveFile`, `MoveFolder`, `handoverFolder`, and any future one) must set both columns through `names.seal`; reads decrypt in `scanFile`/`Folders`, so `File.Name`/`Folder.Name` stay plaintext for callers and a wrong key fails the read. `Files`/`Folders` sort by name in Go with `strings.Compare` (SQLite BINARY order). Never filter or order by `name` in SQL. Schema 4 seals existing names in its transaction; `scrub` then runs `VACUUM` and a truncating WAL checkpoint, tracked by `drive_name_scrub` so a crash repeats it; the marker is dropped only when the checkpoint reports `busy=0`, so a reader in another process defers the scrub to the next start instead of leaving plaintext in the WAL. `New` refuses a key that is not 32 bytes, before touching the database, and `checkKey` records a key fingerprint in `drive_key` on first open and returns `ErrWrongKey` for any other key before migrating, so a regenerated key cannot mix new ciphertext with unreadable old rows and blobs. Workspace and service-token names stay plaintext.
- `SealLegacyBlobs` seals plaintext blobs written before encryption: a checked sealed copy under a new ID, then one transaction moving every `drive_versions` row from the old ID and inserting it into `drive_blob_retire`, then removal after commit. Every run finishes pending retire rows first and never removes a retired ID that is referenced again. A swap that finds no rows (purged meanwhile) discards its copy; bytes that differ from their digest stay plaintext and are logged.
- Client mtime (`drive_versions.mtime`, `Version.Mtime`) is optional metadata and never changes content. `Mtime` validates it (RFC 3339, from 1970 to one day ahead, else `ErrInvalid`) and normalizes to UTC; `Publish` and `StartUpload` call it, and an upload session stores it until `CompleteUpload` publishes. Reads go through `versionMtime`: `File.Mtime` (json `mtime`) falls back to the version's `created`. Only `Publish` callers set one; copies, restores, editor saves and guest uploads get their creation time. `mtime_test.go`.
- Publish immutable, generated blob IDs before transactionally committing version metadata. Check expected revisions and quotas under the transaction. Do not derive disk paths from user filenames.
- `SweepOrphans` removes `.upload-*` staging files and canonical-UUID blobs that no `drive_versions` row names, only when older than its grace (the API passes 1h), so an upload between rename and commit is never touched; other names are left alone. `drive_versions.blob` is the only blob reference (`drive_blob_retire` lists unreferenced IDs awaiting removal).
- `thumbs.go`: `Thumbnail` makes a PNG inside `ThumbnailSize` square from PNG, JPEG, GIF or WebP recognised by magic bytes, refusing (`ErrNoThumbnail`) files over `ThumbnailMaxFile` and any image whose `DecodeConfig` exceeds 16384 px a side or a 256 MiB decoder budget (the measured allocation of each decode path, rounded up and pinned by `TestDecoderCostsHold`: PNG 4, 8 at 16 bits including 16-bit gray, which decodes as NRGBA64 with transparency, doubled when interlaced; GIF 4; WebP 12, lossy with palette-coded alpha measuring 9.3; JPEG by `jpegCost`, gray 4/16, three components 8/20 as RGB whatever `DecodeConfig` says, since an Adobe marker after the scan makes RGB, CMYK 9/25, baseline/progressive, where a frame the walk, as lenient as `image/jpeg`, does not find to be baseline counts as progressive) before decoding; one image decodes at a time and JPEG EXIF orientation is applied. `WriteThumb`/`ReadThumb`/`OpenThumb` (streaming) seal the cache under the cache binding at `<root>/<blob>`, named by blob ID (a digest name would let a disk reader confirm content), so `SweepOrphans` on the thumbnail root removes thumbnails of purged blobs. `TestThumbnailRefusesBombs`, `TestThumbnailScales`, `TestThumbnailCacheIsSealed`.
- Quota usage (`usedBytes`) sums plaintext `drive_versions.size` per row, the same rows purge and retention delete; copies count per row though they share a blob, and sealing overhead is not counted. `drive_files_workspace` indexes it (`editor_test.go` checks the plan).
- SQLite is the initial supported drive database. Keep domain inputs independent of HTTP.
- Tenancy (`tenancy.go`, design `docs/superpowers/specs/2026-11-20-tenancy-design.md`): `New` first records `server_settings.tenancy_mode` (`single`, the only mode this release opens) and refuses a database recorded otherwise (`recordTenancy`). Schema 27 creates `drive_orgs(id, status, revision, enabled, storage_bytes, purged, seeded, retention_after)`, seeding the default org `DefaultOrg` only on a database recorded single, and adds `org_id` (default `DefaultOrg`; nullable only on `audit_records` and `drive_events`) to every org-owned table, with triggers: `<table>_org_exists` (insert into a missing or `deleted` org), `<table>_org_fixed` (org_id never changes), `<table>_one_org_insert`/`_update` on `group_members`, `drive_personal_workspaces`, `drive_grants`, `drive_suite_groups`, `drive_shares` (user and group principals) and `drive_link_users` (both sides in one org, a missing side refused; updates checked only when a paired column changes), `drive_versions_one_org_*` (a blob named by another org's version) and `drive_files`/`drive_folders` `_one_org_move`. Every message starts `tenancy:`, which `transaction` reports as `ErrDenied`. Scoping (`tenancy.go` fragments): `activePrincipal(u)` (active account in an active, enabled org) replaces every inline `status='active'`, and `Store.ActivePrincipal` / `store.ActivePrincipal` give it to sessions and sign-in; `rankSQL` and `itemRankSQL` grant nothing outside `sameOrg(u, w)`; every insert into an org-owned table sets `org_id` from `userOrg` or `workspaceOrg`; `resource`, `File` and `MoveFolder` load only the caller's org, so a cross-org ID answers like a missing one. `TestOrgSQLNamesOrgID` scans drive, store and api SQL: a text naming an org-owned table must name `org_id`, call one of those fragments, or have its declaration in `orgSQLAllowlist` with a reason. `Open` takes a `Tenancy` (`New` is single-tenant); a multi-tenant one records `staff_org` beside `tenancy_mode`, refuses a database recorded with another, and seeds the staff org row (`seeded=1`). Schema 28 (`staffAdminSchema`) refuses `role='admin'` outside the staff org on a multi-tenant database, and `admin` checks the same (`staffSQL`). Administrators act in the org `WithOrg` names (staff's `X-Ky-Org`), else their own (`adminOrg`): `Events`, `Leavers`, `Colleagues`, `Handover`, `DeletedWorkspaces`, `RestoreWorkspace`, the admin `Workspaces` list and the admin path of `Grant`/`Grants` (`adminIn`) see only that org, and `event` records staff actions there. `CreateWorkspace`, `RenameWorkspace`, `DeleteWorkspace`, `Quota` and `SetRetention` answer `ErrNotFound` on a multi-tenant store (`singleTenant`, D10). The org registry (multi-tenant only): `ApplyOrgs` upserts `suitedir.Orgs` pages in one transaction (newer revision only, never the `seeded` staff row; `storage_bytes` only from a positive integer `quotas.storage_bytes`, else NULL) and records the next `since` in `server_settings.orgs_since` (`OrgsSince`); `OrgActive` and `UserOrg` serve the sign-in checks, and `ActiveOrgs` (active and enabled) the per-org suite group poll. A multi-tenant `recordTenancy` also creates `idx_users_kysignon_subject`, unique on `users(sso_subject)` for `kysignon` rows, so a subject is one account. `OpenMulti` (tests only) opens a multi-tenant store for `tenancy_scope_test.go`. A new table must join one class list in `tenancy_classes_test.go` (`TestEveryTableIsClassified`), and a new org-owned table needs its own schema entry: schema 27's list is frozen (`TestOrgOwnedTablesHaveOrgID`, `TestMultiTenantRefusesDefaultOrg`, `TestTenancyTriggersKeepRowsInOneOrg`, `TestTenancyUpgradeKeepsEveryRow`).
- Drive schema changes are append-only entries in `schema.go`, applied once each and recorded in `drive_schema`. Name insert columns explicitly so added columns do not break inserts. Never edit a shipped entry.
- PostgreSQL (tenancy R1; `pg` when `qmark.Is(db)`): a PostgreSQL drive is always new, so `createPostgres` writes the whole schema at `postgresVersion` in one transaction (`schema_postgres.go`) and records versions 1 to it. A new `schema` entry needs its PostgreSQL form there too; `TestPostgresSchemaIsCurrent` and `TestBackendsHaveTheSameColumns` (every table, column, index and trigger, run in CI's `postgres` job) fail until it has one. SQLite's INTEGER is BIGINT there; `org_id` is also a foreign key to `drive_orgs`.
  - Triggers come from `dialect.trigger` for both backends (PL/pgSQL with the same names and messages); SQLite's `IS NOT` between values is `dialect.isNot`. The shared SQL may call SQLite's `julianday`, `unixepoch()`, two-argument `max`/`min` and `printf('%020d',…)`, which PostgreSQL gets as functions; anything else must be portable. A parameter selected as a column needs `CAST(? AS TEXT)`; an upsert's `DO UPDATE` names the table on its columns.
  - Every PostgreSQL transaction is serializable (`qmark.Open`). `transaction` reruns `f` through `qmark.Retry` on a serialization failure or deadlock, so `f` must only touch the database, and every variable from outside `f` that it writes (bar `err`) is set in its leading statements (a zero value, or a copy taken before the call), so a rolled-back run leaves nothing behind. `TestRerunClosuresResetWhatTheyWrite` checks this for drive and main-store closures, and that nothing is called after a closure's `Commit` (a failure there would rerun committed work). A count kept across calls is updated after `transaction` returns. A step a transaction goes on from after it fails (trying another name) runs in `attempt`, a savepoint there.
  - `drive_changes_in_order` (PostgreSQL only) takes a change row's seq under its workspace's transaction lock, so rows of one workspace commit in seq order.
- Only unique-constraint violations (`uniqueViolation`: SQLite's message or SQLSTATE 23505) and domain state checks map to `ErrConflict`; wrap it with a short reason (`fmt.Errorf("%w: name exists", ErrConflict)`), which the API returns to the client. Unknown ids map to `ErrDenied`/`ErrInvalid` only on `sql.ErrNoRows`; other database errors pass through.
- Trash is batched: trashing a folder trashes its live subtree under one `trash_batch`; restore brings back that batch only; an item whose parent is still trashed returns to the workspace root. Trashed folders cannot receive items. `SetFolderTrash` authorizes before reporting state, so an unauthorized caller gets `ErrDenied` whether the folder is live, trashed or missing. Trash, restore and moves authorize through the item's parent (a folder's parent; a file's parent without the file's own share), as a rename does, so a share on an item never lets its holder trash, restore or move that item; a restore that lands at the workspace root needs editor there (`TestShareHolderCannotRemoveTheSharedItem`). `SetFolderTrashSince(user, id, trash, head)` is `SetFolderTrash` on condition, checked in its transaction before its change row: a `drive_changes` row after `head` naming the folder or a live folder or file beneath it, or `head` below the workspace's floor, is `ErrConflict` and changes nothing; changes elsewhere in the workspace do not count (`TestFolderTrashSinceHead`).
- Moves never create versions. A same-workspace file move needs editor; a cross-workspace file move needs rank 3 (manager or personal owner) on the source and editor on the target, plus target quota for every version, and, in the same transaction, revokes every open editor session on the file, closes its editor documents and increments `drive_files.editor_epoch` (sessions may come from a credential scoped to the source; closed documents refuse in-flight callbacks). Trash and editor-session writes require the workspace they authorized. Folder moves stay in their workspace and cannot enter their own subtree. A live file and a live folder never share a name in one parent: schema 20 triggers on both tables refuse any insert or name, parent, workspace or restore change that would clash, with a `UNIQUE constraint failed` message that `uniqueViolation` maps to `ErrConflict` (`TestFileAndFolderNeverShareAName`). Schema 20's transaction renames the file of every clash made before it (both live, or both trashed) to the first free `numbered` name, extension kept and cut to 255 bytes (`clashName`), loading folder places once (no index serves an all-states lookup), with a change row and a `file.renamed` event by `system` (`renameClashes`, `TestClashSchemaRenamesExistingClashes`), so handover and restores never trip the triggers. Copies share the immutable blob and count against target quota. Copy and restore read the reused blob inside their publishing transaction.
- Purge needs rank 3 through the item's parent, as trash does (a folder's parent; a file's parent without the file's own share, for `PurgeFile` and `PurgeVersion`), so a share on an item never lets its holder purge it or its versions; inside a folder shared as manager purges still work (`TestShareHolderCannotPurgeTheSharedItem`). `purgeFile` fails closed before any delete: unknown is `ErrDenied`, a live file is `ErrConflict`. Purging a file or a non-current version is blocked while any matching editor session has `drop_done=false`, including expired sessions the revocation worker has not swept, so Euro-Office always receives its drop before the rows go.
- Retention: `trash_days` and `keep_versions` per shared workspace, admin-set (`SetRetention`); personal workspaces are refused with `ErrDenied`. `ApplyRetention(ctx, at, trashDays)` takes the drive-wide trash age (0 = off), which empties the trash of every workspace, personal ones included, whose own `trash_days` is 0; a workspace's non-zero `trash_days` overrides it. `keep_versions` 0 is off; N keeps the newest N versions that exist, counted, so gaps a manual purge left are not counted as kept (`TestRetentionKeepsExistingVersionsAcrossGaps`). `ApplyRetention` pages by cursor so stuck items cannot starve later ones, re-checks each item's policy inside that item's own transaction, writes `file.retention_purged`, `version.retention_purged` and `folder.retention_purged` as actor `system`, and logs one line with the skipped count when above 0. Empty expired trashed folders only. `export_test.go` exposes test hooks (`PurgeFileUnauthorized`, `ExecSQL`, `QueryInt`, `RetainFile`, `RetainVersion`).
- Change log (`changes.go`): `drive_changes(seq, workspace, kind, item)` orders every content change per workspace. `change(ctx, tx, workspace, kind, item)` is written in the mutation's own transaction, beside its `event`, by `publishTX` (so `Publish`, `RestoreVersion`, `CopyFile`, `PublishEditor`, `GuestUpload`, `CompleteUpload`), `AddFolder`, `moveFile` (source and, when it differs, destination), `MoveFolder`, `setTrash`, `SetFolderTrash` and `SetFolderTrashSince` (the subtree root only) and `handover` (each top-level source item, and the new folder in the target). Purges, retention, grants, shares, links and quotas write none: they touch only trashed items or access. A new item mutator must write its row; `TestEveryMutatorWritesAChange` fails until every exported `Store` method is either in its table or classified in `noChange` with a reason. `PruneChanges(before)` deletes older rows except each workspace's newest and raises `drive_change_floor` to the highest seq it deleted there.
- Change readers (`changes.go`) authorize rank 1 on the workspace (`authorize`, so a service token only for its own workspace) inside the one transaction they query in, and decrypt through `queryFolders`/`queryFiles`, which take that transaction (the pool has one connection). `Changes(after, limit)` returns `ErrGone` when `after` is below the workspace's floor, else each item named by the next `limit` rows once, in first-appearance order: live state from this workspace, or `Removed` with no metadata when it is trashed, purged or elsewhere, so a move never reveals its destination. `Snapshot(afterID, limit)` pages live folders and files together by ID with `head` (the workspace's newest seq) read in the same transaction; a client must keep the first page's `head` and follow `Changes` from it. `Workspace.Head` carries the same value in listings. `TestSnapshotThenChangesMissesNothing` pins that.
- Handover (`handover.go`): `Handover` needs `admin()` (service contexts refused); `OperatorHandover` is the CLI entry, actor `system:operator-cli`, and also writes `audit_records` with `ip_address='operator-cli'`. One transaction: the source must be a personal workspace whose owner is missing or not `active` (active is `ErrConflict`), the target a shared workspace or an active colleague's My files (created if needed), quota checked once for every version. It creates `Handover from <owner> <YYYY-MM-DD>` (numbered ` (2)`... when taken) at the target root, re-parents root items into it, keeps trashed items trashed with `trashed_at` reset, revokes editor sessions, closes documents, bumps `editor_epoch` and revokes service tokens scoped to the source, and writes one `workspace.handed_over` event with IDs and counts only. An empty source is `ErrConflict` (`nothing to hand over`), so a rerun is harmless. The emptied personal workspace stays, so a reactivated owner gets an empty My files. `Leavers` lists non-empty leaver workspaces (owner label, status `inactive`/`suspended`/`deleted`, bytes, item count) and never file names; `drive_personal_workspaces.owner_name` labels deleted accounts, fallback `a removed account`. An admin who holds a grant on the target sees the moved names like any member. Bringing a leaver's data to zero is a handover to a shared workspace followed by a manager purge.
- Suite groups (`suitegroups.go`, schema 25, contract KyIdentity `docs/SUITE-DIRECTORY.md`): `ReconcileSuiteGroups(ctx, org, []suitedir.Group)` (actor `system`, events in `org`; service, device and peer contexts `ErrDenied`) runs one transaction per group, continuing past a failing one (errors joined, group IDs only). `drive_suite_groups(kyid, workspace, grp)` keys each KyIdentity group ID to one shared workspace and one local group, both in `org` (a `kyid` held by another org is found as absent, and its insert fails on the key) (`display_name` `suite-group:<kyid>`, `external_id` ''); never matched by name or slug, and no row, group or workspace it made is ever deleted. `active`: no row creates workspace (`suiteName`: the name, else the slug when not `ValidName`; on a clash `Name (2)`, `(3)`... through `nameFree`, deleted workspaces included, so a recreated namesake never takes the archived one; quota `suiteQuota` 1 GiB), group, row and editor grant together; a deleted workspace is restored (`restoreWorkspace`); a name that is neither `Name` nor `Name (n)` is renamed to the first free one (none free: logged, kept); the grant is put back to exactly `editor` (`suite_group.grant_repaired`); members become exactly the listed subjects resolved KySignOn-first then SCIM to an `active` `role='user'` account (`suiteMembers`; administrators, the local recovery account and unknown subjects are skipped, and an account in another org is skipped and audited `tenancy.org_mismatch`). `archived`: members emptied, and a live workspace archived by `archiveWorkspace` (the recoverable delete: links, service tokens, rooted agent tokens and editor sessions revoked, items kept), empty or not; no row does nothing. A state other than these two, or absence from the list, changes nothing. Events (resource `<workspace> group=<grp> kyid=<kyid>`, counts only, no names or subjects): `suite_group.created`, `.renamed`, `.restored`, `.archived` (`members_removed=N` and revoked counts), `.members_changed` (`added=N removed=N`), `.grant_repaired`. A second pass over the same input writes nothing. `DeleteWorkspace` archives a suite workspace even when empty (never `removeWorkspace`), and `PurgeDeletedWorkspaces` skips every suite workspace, so they are kept until an administrator acts by hand; an administrator's restore or delete is undone at the next pass while KyIdentity still lists the group otherwise. `suitegroups_test.go`.

## Work Guidance

- Keep edits pure where possible; validate filenames, sizes and revision inputs at boundaries.
- Access is defined once, in `access.go`: `rankSQL(user, workspace)` (workspace grants and personal owners; 0 for a deleted workspace) and `itemRankSQL(user, workspace, folder, file)` (that, raised by `drive_shares` on the file or any ancestor folder, to the active user or their groups; a personal workspace's shares lapse while its owner is inactive, and every share lapses while its workspace is deleted) are the only SQL that computes a rank (0 none, 1 reader, 2 editor, 3 manager). Every item operation uses `authorizeItem`; whole-workspace listings, grants, tokens and quota stay on `authorize`. Service tokens get workspace rank only, never shares. Its arguments are column references. Never compute access anywhere else; extend `rankSQL` instead. A peer context's whole access is `peerAllows`. `TestAccessDefinitionPinsCurrentRules` pins its rules.
- Shares (`shares.go`): workspace managers (and a personal workspace's owner) share an item with a person or group as reader, editor or manager; workspace editors may share up to their rank on the item when the workspace's `editors_share` is on (manager-set, off by default); share holders who are not workspace members never re-share, whatever their share's role (a manager share manages the item but does not pass it on), and an editor cannot change or remove a share above their role. Shares only add, never narrow. `SharedWithMe` lists live items shared with the user at a higher role than their own workspace rank (outside workspaces they belong to, or above their membership, so a workspace reader with an editor share edits from Shared with me; `TestSharedWithMeRaisesAMembersRole`). `People` finds active accounts by name or username (2+ characters, 20 results, never email). Moving a file to another workspace and a leaver handover delete the shares on what moved (handover records `shares_dropped`). `publishTX` updates a file only where its stored parent matches, so a write authorized through a folder cannot reach a file elsewhere; `MoveFile` re-reads the file's workspace and parent inside its transaction, authorizes those, and updates only while they are unchanged.
- Organisation links (`links.go`): 256-bit tokens shown once, stored as SHA-256, granting reader or editor on one item to any active signed-in user who opens it; opening records the user (`drive_link_users`) and is audited, and `itemRankSQL` counts the link only while it is neither revoked nor expired (at most a year). Unusable links of every kind answer `ErrNotFound`. Cross-workspace moves and handovers revoke links on what moved.
- Guest links (`guest.go`): one file or folder for people without an account, view and download only, or upload-only into a folder without listing it; mandatory expiry within the administrator's limit; optional password (`ky-primitives/password`). A guest link works only while its creator could still create it (`mayShare`, plus edit rights for upload-only), so it dies with their access. Guest uploads publish on the creator's authority, numbering a taken name (`name (2).ext`) rather than refusing it, so a guest cannot probe what the folder holds; downloads and uploads are audited as `guest-link:<id>`. Unusable guest links are `ErrNotFound`, a missing or wrong password `ErrPassword`, checked last. Guest links are session-outliving credentials: `RevokeUserCredentials` revokes the creator's (`revoked=1`, never undone, so reactivation revives none); organisation links stay (`TestAccountSecurityRevokesGuestLinks`). The API requires a fresh step-up to create one.
- App passwords (`apppasswords.go`) are HTTP Basic secrets for the user's own WebDAV clients: 160 random bits shown once as eight dash-separated base32 groups, stored only as SHA-256 of the normalized secret (dashes and case ignored), named (plaintext labels, like service tokens), at most 20 per user (agent tokens included), no expiry. Revoking deletes the row. A password change or operator reset, and a directory deactivation (`store.ApplyDirectoryUser`), call `RevokeUserCredentials` in their transaction: it deletes the account's app passwords, agent tokens and device codes, revokes its service tokens and guest links and revokes its devices without wipe. `AppPasswordUser` accepts only `scope='dav'` rows with a matching username (any case) of an `active` account (a suspended local account's passwords stop on the next request); `last_used` is written at most every 5 minutes. A service or device context can never create one. Events: `app_password.created`, `app_password.revoked`.
- AI agent tokens (`apppasswords.go`, schema 15) share the table: `scope` `mcp:read` or `mcp:write` (existing rows are `dav`), `kya_` + 160 random bits, hashed like app passwords, optionally limited by `root_workspace`/`root_folder` (folder `''` = the workspace root), which `CreateAgentToken` requires to be live and readable by the user. `AgentTokenUser(token, at)` matches only agent scopes of an active user, so neither credential works as the other. A token unused for `AgentIdleLimit` (90 days, from `last_used` or else `created`) is deleted and refused at sign-in; `ExpireAgentTokens(at)` sweeps the rest; both write `app_password.expired`. `SetAgentScope` moves the user's own token between the two agent scopes (`ErrInvalid` for WebDAV rows, `ErrDenied` for others' IDs; event `app_password.scope_changed`). `CreateAgentToken` and `SetAgentScope` refuse service and device contexts. The root limits what the API resolves; the store still authorizes every operation as the user.
- Device credentials (`devices.go`) are linked computers' bearer tokens, separate from app passwords and service tokens. `ApproveLink` (signed-in user, never a service or device context) takes a name (`ValidName`, at most 100 bytes), a platform (`windows`/`macos`/`linux`), an S256 PKCE challenge (base64url of 32 bytes) and a loopback redirect: exactly `http://127.0.0.1:<port>` or `http://[::1]:<port>` plus an optional path, canonical spelling only (no names such as `localhost`, userinfo, query or fragment, at most 200 bytes, RFC 8252 §7.3). It returns a 256-bit one-time code stored as SHA-256, valid 60 seconds. `RedeemLink(code, verifier)` spends the code with one conditional UPDATE in the transaction that checks expiry and the RFC 7636 verifier (43-128 unreserved characters) in constant time; every failure is `ErrDenied` and a wrong verifier still commits the burn. It mints `kyd_` + 256 random bits (base64url), stored as SHA-256. `ApprovePhone(user)` (same refusals as `ApproveLink`) stores a phone code with empty name, platform and challenge, valid 120 seconds; `RedeemPhone(code, name, platform)` takes `android`/`ios` and the phone's own name and spends it the same way. Both share `redeem`, whose check keeps the two kinds apart: a computer code needs a non-empty challenge matching the verifier, a phone code an empty one, and a cross attempt burns the code (`TestPhoneLink`). Both steps require an active user with fewer than 20 unrevoked devices (`ErrQuota`). `DeviceUser` accepts a token only for an active user, unrevoked and used within 90 days, writing `last_used` at most every 5 minutes; a token revoked within 30 days returns `ErrDeviceRevoked{Wipe}` (which also `errors.Is` `ErrDenied`), anything else `ErrDenied`. `RevokeDevice(user, id, wipe)` sets `revoked_at` and `wipe` on the user's own live device; the caller decides `wipe` (the API enforces the admin policy). `UnlinkDevice(user, token)` revokes the presenting token's own device with `wipe=false` (the client unlinked itself). `PruneDevices` deletes rows revoked over 30 days ago, live rows idle over 90 days and expired codes. `WithDevice` marks a device context, which syncs files and nothing more: `admin()` and every method that creates or changes access or mints a session or credential refuse it with `ErrDenied` (`EditorSession`, `Share`, `Unshare`, `SetEditorsShare`, `Grant`, `AuthorizeSharedManager`, `CreateLink`, `RevokeLink`, `OpenLink`, `CreateGuestLink`, `CreateServiceToken`, `RevokeServiceToken`, `CreateAppPassword`, `RevokeAppPassword`, `ApproveLink`, `RevokeDevice`). So no editor session, share or link ever comes from a device, and revoking one needs no teardown. Reads, uploads, folders, moves, copies, trash, restore and purges stay allowed. `devices_access_test.go` classifies every exported Store method as allowed, refused or unreachable with a device, and fails on an unclassified one. Events: `device.linked`, `device.revoked` (resource `<id> wipe=<bool>`). `RedeemLink`/`RedeemPhone` require a P-256 SPKI key (`ParseDeviceKey`; missing or anything else `ErrInvalid` before the code is spent) stored in `drive_devices.pubkey` (schema 26); `DeviceUser(ctx, token, verify)` calls `verify(id, key)` right after the row is found and returns its error, before revocation, idle or `last_used` are revealed or written (`TestDeviceVerifyRunsBeforeRevocationOrUseIsRevealed`); for a device linked before signing (nil key) it calls `verify` after the revocation and idle checks, so it is still told to wipe (`TestKeylessDeviceIsToldItWasRevokedThenRefused`).
- `Lookup` and `Children` (`lookup.go`) authorize rank 1, then select live rows by `parent` and, for `Lookup`, by `name_hmac` equality only; they decrypt just those rows. `ErrNotFound` (HTTP 404) means no live item has the name; it is returned only after authorization, so it never reveals another workspace. `Folders` and `Files` share the same decrypt-and-sort helpers.
- `SearchFolder` is `Search` within one folder's live subtree (`''` = the whole workspace), paths relative to it, after a rank-1 check on the folder. `FolderPath` (`lookup.go`) returns the decrypted names from the workspace root to a live folder the user can read, `ErrNotFound` when it or an ancestor is trashed, gone or elsewhere.
- `Search` (`search.go`) lists readable workspaces through `Workspaces`, loads live names through `Folders`/`Files` (each authorizes), and matches decrypted names case-insensitively in Go; 2–100 runes, sorted by lowercase name then path, capped by the caller (HTTP: 200). Names match `nameQuery(q)`: the content syntax removed (double quotes, a `*` ending a word); syntax alone matches no name. `SearchContent`/`SearchFolderContent` also pass exactly those readable live files, and the query as typed, to a `ContentMatcher`; `SearchContent` with `shared` (HTTP, not MCP) adds `searchShared`: the `SharedWithMe` items whose workspace is not already searched, a file alone or a folder and its live subtree (`matchNames`, the same name and type rules), each hit with `Shared` (`From` = the list's `WorkspaceName`, `Role`) and a `Path` starting at the shared item; an item inside an earlier shared folder is taken once; service, device and peer contexts get none; after sorting and the limit every shared hit is re-checked (`stillShared`: live, and `File`/`authorizeItem` reader) and dropped if access ended (`TestSearchSharedWithMe`: every way access ends, a revocation during matching, types, administrators, service and device contexts); name matches come first (`match` `name`, plus `content` when it matched too), then content-only matches by score. A nil matcher is name search. A type (`types.go`: `typeExtensions` maps documents, spreadsheets, presentations, pdfs, images, videos, audio and archives to extensions; `folders` is the other) keeps only folders, or files whose last extension (case-insensitive) is in the type, before name and content matching, so the matcher only sees those files; with a type `q` may be empty (every name matches, no content match). `ValidType` gates it; an unknown type is `ErrInvalid`. No type is stored. `IndexChanges`, `IndexFile` and `IndexFiles` are the search worker's drive-wide reads (no user, never reachable from a request). `TestSearchScale` pins 50 000 names; move to an index only if that is measured too slow, and never one that reveals name substrings.
- `FolderTree` (`zip.go`) reads a live folder and its live descendants in one transaction after a read check on the workspace, with paths built from decrypted names rooted at the folder's name. When M3 adds folder or file grants, it must recheck every member.
- Upload sessions (`uploads.go`) belong to their creator, expire 24h after start, and are capped at 8 open per user and at the caller's `max` and free quota at start (`Publish` rechecks quota). Every call rechecks edit access. Each append is sealed in the blob format to its own `<staging>/<session>/<uuid>` segment (via `.part-*`, fsynced) before one transaction advances `received` from exactly `start`; the loser of a race deletes its segment. Staging never holds plaintext. `CompleteUpload` first claims the session (`completing`, one conditional UPDATE) so only one completion re-seals at a time; a second gets `ErrConflict` before writing anything, a failure releases the claim, and a crashed request's claim expires after 30 minutes; a running completion renews its claim every 10 minutes until it ends (`claimCompletion`), since completion has no time limit (`TestCompletionClaimHoldsAgainstExpiry`). It streams the segments through `WriteBlob` and `Publish`, then deletes the session and its directory; a failed publish removes the new blob, and a cleanup failure after a successful publish is logged, never returned (`TestCompletionSucceedsWhenCleanupFails`). `ExpireUploads` drops expired sessions whose completion claim has lapsed, rechecked in each deleting transaction (`expireUpload`); `CancelUpload` refuses such a session the same way (`ErrConflict`, checked before the deletes in their transaction, `TestCancelWaitsForACompletionClaim`); and hour-old staging directories with no session (`TestCompletionClaimHoldsAgainstExpiry`). Staging is not user data: outside backups, safe to delete. Only start and cancel write events; the version event comes from `Publish`.
- KyPost (`peer.go`, `access.go`; contract `docs/KYPOST.md`, schema 21): `WithPeer` marks a peer context, KyPost acting for one user. It holds no rank: `authorize`, `admin`, `Workspaces`, `EnsurePersonalWorkspace`, `SharedWithMe`, `People`, `AppPasswords`, `Devices`, `CancelUpload` and every `narrowed` check (device or peer: no access change, session or credential) refuse it, and `authorizeItem`/`mayShare` admit it only through `peerAllows`: `peerAdd` (marked on ctx only by `startUpload` and `Upload` for a new file and by `publishTX` for revision 1) adds a new file directly in the user's `drive_peer_folders` folder, live, in their own live My files; `peerLink` (marked only by `CreateLink`) is a reader link on a live file directly in it. `peerRead` (marked only by `PeerFetch`, through `authorizeItem` with need 1: `peerReads`) reads a file the user picked (`drive_peer_picks`, unexpired) and still holds reader rank on; `PeerFetch` also refuses a trashed file (`TestPeerFetch`). Both, and `IssueTicket`, first read the user's switch in the same transaction (`peerSwitch`: the stored choice, else `WithPeer`'s default) and return `ErrPeerOff` when it is off, and `ErrPeerGone` when `WithPeer`'s `Peer.Live` says the pairing it came under has ended; `TicketUpload` then drops the session and ticket (`TestTicketSwitchOffMidUpload`, `TestTicketUnpairedMidUpload`). A ticket stores `Peer.Pairing` (the API's keyed pairing fingerprint; `IssueTicket` refuses an empty one) and `TicketUpload` refuses it, `ErrPeerGone`, under any other (`TestTicketBoundToItsPairing`). `peer_access_test.go` classifies every exported Store method as peer allowed, refused (each proven `ErrDenied` with arguments that succeed without it) or unreachable, and fails on an unclassified one. `IssueTicket` (peer only) stores SHA-256 of a 256-bit token, the sealed name (`drive_peer_tickets`, name binding `drive_peer_tickets:<id>`), size and a 15-minute expiry, after `ValidName` of the name and its ` (100)` numbering, `size <= max` (`ErrTooLarge`), `fits` on My files (`ErrQuota`) and at most 8 live (`ErrTicketLimit`); event `kypost.ticket_issued`. `TicketUpload` runs as the owner in a peer context through the ordinary session path: the first request (start 0, else `ErrConflict`) makes or remakes the folder (`peerFolder`: recorded, else adopt a live root folder named `Mail attachments`, else create it numbered past a file of that name), opens a session expiring with the ticket under the first free numbered name and binds it with one conditional UPDATE (a concurrent loser drops its session); the last bytes complete it, renumbering if the name was taken meanwhile (`errNameTaken`), delete the ticket and write `kypost.file_saved` (`<file> peer=kypost ticket=<id>`). `ExpireTickets` deletes expired rows; `ExpireUploads` discards their bytes. `PeerSetting`/`SetPeerSetting` (`drive_peer_settings`, refused for service, device and peer contexts; event `kypost.switch_changed`) store the user's switch; `PeerFree` is My files' free quota (a new one's when absent). `PeerGuestLink` (peer only) is `CreateGuestLink`'s path under `peerLink` for a view guest link on a Mail attachments file, refused `ErrPeerGuestOff` in its transaction unless `drive_peer_guest` (schema 23) holds the user, event detail `peer=kypost`; `PeerGuestSetting`/`SetPeerGuestSetting` (set refused for service, device and peer contexts; event `kypost.guest_switch_changed`) read and store that switch. `RecordPicks` (session only: refused for service, device and peer contexts; `liveLogin`, `mayShare` reader, live file) upserts `drive_peer_picks` (schema 22) for `PickLife` (24 h), event `kypost.file_picked`; `ExpireTickets` also deletes expired picks. `peer_test.go`.

- Viewing copies (`viewcopies.go`, schema 24 `drive_view_copies`; contract `docs/KYPOST.md` "Viewing copies"): `IssueViewTicket` (peer only, `Pairing` required) checks `ViewKind` (docx, xlsx, pptx, odt, ods, odp, csv, pdf), `ValidName`, size 1..min(max, `ViewMaxBytes` 25 MiB), `peerSwitch`, `fits` and 4 live per owner (`ErrTicketLimit`), seals the name (binding `drive_view_copies:<id>`) and stores the token hash with a 15-minute ticket and 24-hour (`ViewLife`) expiry. `StoreViewCopy` (peer, same `Pairing`, else `ErrPeerGone`) sniffs the first 512 bytes (`viewSniffs`, else `ErrUnsupported`), writes exactly `Size` bytes with `WriteBlob` into the caller's root (the API's `<data>/view`, never `<data>/blobs`), and spends the ticket with one conditional UPDATE re-reading the switch; any failure removes the blob. `usedBytes`, `PeerFree` and `Workspaces` count every copy's size from issue (`viewBytes`). `ViewCopy` and `CloseViewCopy` refuse service, device and peer contexts (`signedIn`) and match the owner; `ViewCopy` checks `liveLogin` and records the `WithLogin` binding (`sso_sid`, `login_at`, at least 1) on the first open only, refusing (`ErrNotFound`) any other sign-in, and the table's `user_id`/`sso_sid`/`login_at`/`service_token` columns let `revokeEditors` set `revoked` on copies with the same filter as editor sessions; `CloseViewCopy` deletes an unopened copy but only revokes an opened one (bytes returned for removal) so its drop is kept until delivered; `viewBytes` and the live limit skip revoked rows; `ViewDownload` (Euro-Office, opened and unrevoked copies only) and `ViewClosed` (its status 4) take only the ID; `PendingViewDrops`/`MarkViewDropped` (flat one-minute retry) feed the API's drop of revoked opened copies; `ExpireViewCopies` revokes expired opened copies (bytes returned, row kept for the drop), deletes unopened ones, unused tickets, delivered drops and anything `editorGrace` past expiry, and returns blobs. Copies are not items: no change rows, no access through `rankSQL`. `viewcopies_test.go`.
- Editor document keys are `<file>-<revision>` at epoch 0 and `<file>-<revision>e<epoch>` after a cross-workspace move or a user revocation (`DocumentKey`, `ParseDocumentKey`); sessions store the key's base revision and epoch so revocation drops target the key they opened. `EditorSession` joins an open (`closed=false`) document whose `current_revision` is the file's revision at the current epoch, so a force-save never splits co-editors across keys; a key closed without saves (`CloseEditor`, Euro-Office status 4) reopens. `EditorDownload` serves the document's `current_revision`; the caller verifies Euro-Office's signature, the session row holds no download credential. Editor revision pointers and save digests make force-save sequences atomic: a save is a duplicate only when its digest is the document's newest save, so A, B, A publishes A again. Competing uploads conflict; session rows survive user deletion for revocation delivery.
- `RevokeUserEditors(ctx, tx, user)` revokes a user's editor sessions and bumps `editor_epoch` on their files inside the caller's transaction (nil store is a no-op); `internal/store` calls it wherever it revokes an account's sessions. Editor sessions are also bound to the sign-in that opened them: `WithLogin` (set by the API for every cookie request) gives `EditorSession` the browser session's token hash, SSO `sid` and sign-in time, stored as `sso_sid` and `login_at` (Unix nanoseconds; schema 17), and `EditorSession` refuses (`ErrDenied`) when that browser session is already gone; `CreateAppPassword`, `CreateAgentToken`, `CreateServiceToken`, `CreateGuestLink` and `ApproveLink` refuse the same way inside their creation transaction (`liveLogin`), so a request authenticated before a logout or password reset mints nothing after it (`TestCredentialsNeedALiveLogin`). `RevokeSSOEditors(sid)` and `RevokeUserEditorsBefore(user, cutoff)` revoke by that binding, so back-channel logout reaches editor sessions whose browser session expired and was pruned. Schema 17 revokes, once, the open editor sessions of non-local accounts that predate the binding. A session opened through a service token stores its ID (`service_token`, schema 19, from `ServiceAccess.Token`): `RevokeServiceToken` revokes those sessions in its transaction and `PendingRevocations` revokes them once the token is revoked or expired, or no longer carries the session's rank: the token's role and its owner's workspace rank without shares, as `authorize` checks a service request (`TestServiceTokenEditorSessionsEndWithTheToken`, `TestServiceTokenEditorEndsWithTheIssuersWorkspaceGrant`); the drop names the token's owner, so the owner's own open editor on that document reconnects. Schema 19 revokes, once, open sessions with no sign-in binding (`login_at` 0): service-token sessions and local sign-ins older than schema 17, whose open editors reconnect (`TestServiceTokenSchemaRevokesUnboundSessions`). Other users still on the old key keep saving to it; new openers get the new key, so whichever document saves second conflicts.
- Session expiry (12h) gates downloads only. `CallbackActor` ignores age; the sweep in `PendingRevocations` revokes an expired session once its document is closed, or `editorGrace` (7 days) after expiry if Euro-Office never closes it, so a connected editor is not dropped mid-edit and purge is never blocked for good. Drops are retried in `next_attempt` order; `DeferRevocation` backs a failed drop off from 2s doubling to 1h, so failing drops queue behind new ones.
- Roll back only to a version that understands personal ownership after private workspaces are created; earlier versions do not provide personal access or filtering.
- Service credentials are hashed, workspace-scoped reader/editor grants tied to current issuer membership and expire after 90 days.
