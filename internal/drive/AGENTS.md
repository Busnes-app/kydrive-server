# Drive domain

## Purpose

Own personal and organization workspaces, files, folders, immutable versions and group access grants.

## Ownership

Own drive schema and domain operations over the application's database and blob directory. Identity rows remain owned by the inherited identity stores.

## Local Contracts

- Shared documents belong to workspaces, independent of user deletion.
- Personal workspaces are unique per immutable account ID, default to 10GiB, and allow only the active owner; an admin handover may move a leaver's tree into a shared workspace or a colleague's My files, without granting the admin read access. Group grants and shared-directory management are rejected for personal workspaces, including administrator grants. Retain ownership/data after offboarding until an admin handover; session revocation covers both personal and shared files.
- Read current user status and group memberships when authorizing each operation. Global admin can manage workspace configuration; shared content requires an explicit group grant and personal content requires the active owner.
- Blob encryption (`sealed.go`): `WriteBlob` always seals. Format: `KYB1` || 32-byte random salt, then AES-256-GCM chunks of 64 KiB plaintext under `HKDF-SHA256(deployment key, salt, "kydrive:blob")`; nonce = 11-byte big-endian chunk index || final flag (1 on the last chunk only); the 36-byte header is every chunk's AAD; empty plaintext is one empty final chunk. `SealedSize` is exact. Keys never depend on file ID because `CopyFile` and `RestoreVersion` share blobs. `OpenBlob` requires the exact sealed size, authenticates the last chunk on open and each chunk before returning any of its bytes. `drive_versions.sealed` travels with the blob ID on copy and restore; `digest` and `size` describe plaintext.
- Name encryption (`names.go`): `drive_files.name` and `drive_folders.name` hold `crypto.EncryptAESGCMAAD(name, HKDF-SHA256(deployment key, "kydrive:name"), "<table>:<row id>")`, so a name cannot be moved to another row. `name_hmac` = hex HMAC-SHA256(HKDF-SHA256(deployment key, "kydrive:name-hmac"), name); the live-name unique indexes `drive_live_names`/`drive_live_folders` are `(workspace,parent,name_hmac) WHERE trashed=false`, keeping exact case-sensitive uniqueness while restore and moves change only `parent`/`workspace`. Equal names share an HMAC across the database (equality leaks, content does not). Every write that sets a name (`AddFolder`, `publishTX`, `MoveFile`, `MoveFolder`, `handoverFolder`, and any future one) must set both columns through `names.seal`; reads decrypt in `scanFile`/`Folders`, so `File.Name`/`Folder.Name` stay plaintext for callers and a wrong key fails the read. `Files`/`Folders` sort by name in Go with `strings.Compare` (SQLite BINARY order). Never filter or order by `name` in SQL. Schema 4 seals existing names in its transaction; `scrub` then runs `VACUUM` and a truncating WAL checkpoint, tracked by `drive_name_scrub` so a crash repeats it; the marker is dropped only when the checkpoint reports `busy=0`, so a reader in another process defers the scrub to the next start instead of leaving plaintext in the WAL. `New` refuses a key that is not 32 bytes, before touching the database, and `checkKey` records a key fingerprint in `drive_key` on first open and returns `ErrWrongKey` for any other key before migrating, so a regenerated key cannot mix new ciphertext with unreadable old rows and blobs. Workspace and service-token names stay plaintext.
- `SealLegacyBlobs` seals plaintext blobs written before encryption: a checked sealed copy under a new ID, then one transaction moving every `drive_versions` row from the old ID and inserting it into `drive_blob_retire`, then removal after commit. Every run finishes pending retire rows first and never removes a retired ID that is referenced again. A swap that finds no rows (purged meanwhile) discards its copy; bytes that differ from their digest stay plaintext and are logged.
- Client mtime (`drive_versions.mtime`, `Version.Mtime`) is optional metadata and never changes content. `Mtime` validates it (RFC 3339, from 1970 to one day ahead, else `ErrInvalid`) and normalizes to UTC; `Publish` and `StartUpload` call it, and an upload session stores it until `CompleteUpload` publishes. Reads go through `versionMtime`: `File.Mtime` (json `mtime`) falls back to the version's `created`. Only `Publish` callers set one; copies, restores, editor saves and guest uploads get their creation time. `mtime_test.go`.
- Publish immutable, generated blob IDs before transactionally committing version metadata. Check expected revisions and quotas under the transaction. Do not derive disk paths from user filenames.
- `SweepOrphans` removes `.upload-*` staging files and canonical-UUID blobs that no `drive_versions` row names, only when older than its grace (the API passes 1h), so an upload between rename and commit is never touched; other names are left alone. `drive_versions.blob` is the only blob reference (`drive_blob_retire` lists unreferenced IDs awaiting removal).
- `thumbs.go`: `Thumbnail` makes a PNG inside `ThumbnailSize` square from PNG, JPEG, GIF or WebP recognised by magic bytes, refusing (`ErrNoThumbnail`) files over `ThumbnailMaxFile` and any image whose `DecodeConfig` exceeds 16384 px a side or a 256 MiB decoder budget (the measured allocation of each decode path, rounded up and pinned by `TestDecoderCostsHold`: PNG 4, 8 at 16 bits including 16-bit gray, which decodes as NRGBA64 with transparency, doubled when interlaced; GIF 4; WebP 12, lossy with palette-coded alpha measuring 9.3; JPEG by `jpegCost`, gray 4/16, three components 8/20 as RGB whatever `DecodeConfig` says, since an Adobe marker after the scan makes RGB, CMYK 9/25, baseline/progressive, where a frame the walk, as lenient as `image/jpeg`, does not find to be baseline counts as progressive) before decoding; one image decodes at a time and JPEG EXIF orientation is applied. `WriteThumb`/`ReadThumb` seal the cache with the blob key under `<root>/<blob>`, named by blob ID (a digest name would let a disk reader confirm content), so `SweepOrphans` on the thumbnail root removes thumbnails of purged blobs. `TestThumbnailRefusesBombs`, `TestThumbnailScales`, `TestThumbnailCacheIsSealed`.
- Quota usage (`usedBytes`) sums plaintext `drive_versions.size` per row, the same rows purge and retention delete; copies count per row though they share a blob, and sealing overhead is not counted. `drive_files_workspace` indexes it (`editor_test.go` checks the plan).
- SQLite is the initial supported drive database. Keep domain inputs independent of HTTP.
- Drive schema changes are append-only entries in `schema.go`, applied once each and recorded in `drive_schema`. Name insert columns explicitly so added columns do not break inserts. Never edit a shipped entry.
- Only SQLite unique-constraint violations (`uniqueViolation`) and domain state checks map to `ErrConflict`; wrap it with a short reason (`fmt.Errorf("%w: name exists", ErrConflict)`), which the API returns to the client. Unknown ids map to `ErrDenied`/`ErrInvalid` only on `sql.ErrNoRows`; other database errors pass through.
- Trash is batched: trashing a folder trashes its live subtree under one `trash_batch`; restore brings back that batch only; an item whose parent is still trashed returns to the workspace root. Trashed folders cannot receive items. `SetFolderTrash` authorizes before reporting state, so an unauthorized caller gets `ErrDenied` whether the folder is live, trashed or missing.
- Moves never create versions. A same-workspace file move needs editor; a cross-workspace file move needs rank 3 (manager or personal owner) on the source and editor on the target, plus target quota for every version, and, in the same transaction, revokes every open editor session on the file, closes its editor documents and increments `drive_files.editor_epoch` (sessions may come from a credential scoped to the source; closed documents refuse in-flight callbacks). Trash and editor-session writes require the workspace they authorized. Folder moves stay in their workspace and cannot enter their own subtree. Copies share the immutable blob and count against target quota. Copy and restore read the reused blob inside their publishing transaction.
- Purge needs rank 3. `purgeFile` fails closed before any delete: unknown is `ErrDenied`, a live file is `ErrConflict`. Purging a file or a non-current version is blocked while any matching editor session has `drop_done=false`, including expired sessions the revocation worker has not swept, so Euro-Office always receives its drop before the rows go.
- Retention: `trash_days` and `keep_versions` per shared workspace, admin-set (`SetRetention`); personal workspaces are refused with `ErrDenied`. `ApplyRetention(ctx, at, trashDays)` takes the drive-wide trash age (0 = off), which empties the trash of every workspace, personal ones included, whose own `trash_days` is 0; a workspace's non-zero `trash_days` overrides it. `keep_versions` 0 is off. `ApplyRetention` pages by cursor so stuck items cannot starve later ones, re-checks each item's policy inside that item's own transaction, writes `file.retention_purged`, `version.retention_purged` and `folder.retention_purged` as actor `system`, and logs one line with the skipped count when above 0. Empty expired trashed folders only. `export_test.go` exposes test hooks (`PurgeFileUnauthorized`, `ExecSQL`, `QueryInt`, `RetainFile`, `RetainVersion`).
- Change log (`changes.go`): `drive_changes(seq, workspace, kind, item)` orders every content change per workspace. `change(ctx, tx, workspace, kind, item)` is written in the mutation's own transaction, beside its `event`, by `publishTX` (so `Publish`, `RestoreVersion`, `CopyFile`, `PublishEditor`, `GuestUpload`, `CompleteUpload`), `AddFolder`, `moveFile` (source and, when it differs, destination), `MoveFolder`, `setTrash`, `SetFolderTrash` (the subtree root only) and `handover` (each top-level source item, and the new folder in the target). Purges, retention, grants, shares, links and quotas write none: they touch only trashed items or access. A new item mutator must write its row; `TestEveryMutatorWritesAChange` fails until every exported `Store` method is either in its table or classified in `noChange` with a reason. `PruneChanges(before)` deletes older rows except each workspace's newest and raises `drive_change_floor` to the highest seq it deleted there.
- Change readers (`changes.go`) authorize rank 1 on the workspace (`authorize`, so a service token only for its own workspace) inside the one transaction they query in, and decrypt through `queryFolders`/`queryFiles`, which take that transaction (the pool has one connection). `Changes(after, limit)` returns `ErrGone` when `after` is below the workspace's floor, else each item named by the next `limit` rows once, in first-appearance order: live state from this workspace, or `Removed` with no metadata when it is trashed, purged or elsewhere, so a move never reveals its destination. `Snapshot(afterID, limit)` pages live folders and files together by ID with `head` (the workspace's newest seq) read in the same transaction; a client must keep the first page's `head` and follow `Changes` from it. `Workspace.Head` carries the same value in listings. `TestSnapshotThenChangesMissesNothing` pins that.
- Handover (`handover.go`): `Handover` needs `admin()` (service contexts refused); `OperatorHandover` is the CLI entry, actor `system:operator-cli`, and also writes `audit_records` with `ip_address='operator-cli'`. One transaction: the source must be a personal workspace whose owner is missing or not `active` (active is `ErrConflict`), the target a shared workspace or an active colleague's My files (created if needed), quota checked once for every version. It creates `Handover from <owner> <YYYY-MM-DD>` (numbered ` (2)`... when taken) at the target root, re-parents root items into it, keeps trashed items trashed with `trashed_at` reset, revokes editor sessions, closes documents, bumps `editor_epoch` and revokes service tokens scoped to the source, and writes one `workspace.handed_over` event with IDs and counts only. An empty source is `ErrConflict` (`nothing to hand over`), so a rerun is harmless. The emptied personal workspace stays, so a reactivated owner gets an empty My files. `Leavers` lists non-empty leaver workspaces (owner label, status `inactive`/`suspended`/`deleted`, bytes, item count) and never file names; `drive_personal_workspaces.owner_name` labels deleted accounts, fallback `a removed account`. An admin who holds a grant on the target sees the moved names like any member. Bringing a leaver's data to zero is a handover to a shared workspace followed by a manager purge.

## Work Guidance

- Keep edits pure where possible; validate filenames, sizes and revision inputs at boundaries.
- Access is defined once, in `access.go`: `rankSQL(user, workspace)` (workspace grants and personal owners) and `itemRankSQL(user, workspace, folder, file)` (that, raised by `drive_shares` on the file or any ancestor folder, to the active user or their groups; a personal workspace's shares lapse while its owner is inactive) are the only SQL that computes a rank (0 none, 1 reader, 2 editor, 3 manager). Every item operation uses `authorizeItem`; whole-workspace listings, grants, tokens and quota stay on `authorize`. Service tokens get workspace rank only, never shares. Its arguments are column references. Never compute access anywhere else; extend `rankSQL` instead. `TestAccessDefinitionPinsCurrentRules` pins its rules.
- Shares (`shares.go`): workspace managers (and a personal workspace's owner) share an item with a person or group as reader, editor or manager; workspace editors may share up to their rank on the item when the workspace's `editors_share` is on (manager-set, off by default); share holders who are not workspace members never re-share, whatever their share's role (a manager share manages the item but does not pass it on), and an editor cannot change or remove a share above their role. Shares only add, never narrow. `SharedWithMe` lists live items shared with the user outside workspaces they belong to. `People` finds active accounts by name or username (2+ characters, 20 results, never email). Moving a file to another workspace and a leaver handover delete the shares on what moved (handover records `shares_dropped`). `publishTX` updates a file only where its stored parent matches, so a write authorized through a folder cannot reach a file elsewhere; `MoveFile` re-reads the file's workspace and parent inside its transaction, authorizes those, and updates only while they are unchanged.
- Organisation links (`links.go`): 256-bit tokens shown once, stored as SHA-256, granting reader or editor on one item to any active signed-in user who opens it; opening records the user (`drive_link_users`) and is audited, and `itemRankSQL` counts the link only while it is neither revoked nor expired (at most a year). Unusable links of every kind answer `ErrNotFound`. Cross-workspace moves and handovers revoke links on what moved.
- Guest links (`guest.go`): one file or folder for people without an account, view and download only, or upload-only into a folder without listing it; mandatory expiry within the administrator's limit; optional password (`ky-primitives/password`). A guest link works only while its creator could still create it (`mayShare`, plus edit rights for upload-only), so it dies with their access. Guest uploads publish on the creator's authority, numbering a taken name (`name (2).ext`) rather than refusing it, so a guest cannot probe what the folder holds; downloads and uploads are audited as `guest-link:<id>`. Unusable guest links are `ErrNotFound`, a missing or wrong password `ErrPassword`, checked last.
- App passwords (`apppasswords.go`) are HTTP Basic secrets for the user's own WebDAV clients: 160 random bits shown once as eight dash-separated base32 groups, stored only as SHA-256 of the normalized secret (dashes and case ignored), named (plaintext labels, like service tokens), at most 20 per user, no expiry. Revoking deletes the row. `AppPasswordUser` accepts only a matching username (any case) of an `active` account, so deactivation stops every password on the next request without deleting it; `last_used` is written at most every 5 minutes. A service context can never create one. Events: `app_password.created`, `app_password.revoked`.
- Device credentials (`devices.go`) are linked computers' bearer tokens, separate from app passwords and service tokens. `ApproveLink` (signed-in user, never a service or device context) takes a name (`ValidName`, at most 100 bytes), a platform (`windows`/`macos`/`linux`), an S256 PKCE challenge (base64url of 32 bytes) and a loopback redirect: exactly `http://127.0.0.1:<port>` or `http://[::1]:<port>` plus an optional path, canonical spelling only (no names such as `localhost`, userinfo, query or fragment, at most 200 bytes, RFC 8252 §7.3). It returns a 256-bit one-time code stored as SHA-256, valid 60 seconds. `RedeemLink(code, verifier)` spends the code with one conditional UPDATE in the transaction that checks expiry and the RFC 7636 verifier (43-128 unreserved characters) in constant time; every failure is `ErrDenied` and a wrong verifier still commits the burn. It mints `kyd_` + 256 random bits (base64url), stored as SHA-256. Both steps require an active user with fewer than 20 unrevoked devices (`ErrQuota`). `DeviceUser` accepts a token only for an active user, unrevoked and used within 90 days, writing `last_used` at most every 5 minutes; a token revoked within 30 days returns `ErrDeviceRevoked{Wipe}` (which also `errors.Is` `ErrDenied`), anything else `ErrDenied`. `RevokeDevice(user, id, wipe)` sets `revoked_at` and `wipe` on the user's own live device; the caller decides `wipe` (the API enforces the admin policy). `UnlinkDevice(user, token)` revokes the presenting token's own device with `wipe=false` (the client unlinked itself). `PruneDevices` deletes rows revoked over 30 days ago, live rows idle over 90 days and expired codes. `WithDevice` marks a device context: `admin()` refuses it, as does `CreateServiceToken`, so a device acts with its user's own content rights only and mints no longer-lived credential. Events: `device.linked`, `device.revoked` (resource `<id> wipe=<bool>`).
- `Lookup` and `Children` (`lookup.go`) authorize rank 1, then select live rows by `parent` and, for `Lookup`, by `name_hmac` equality only; they decrypt just those rows. `ErrNotFound` (HTTP 404) means no live item has the name; it is returned only after authorization, so it never reveals another workspace. `Folders` and `Files` share the same decrypt-and-sort helpers.
- `Search` (`search.go`) lists readable workspaces through `Workspaces`, loads live names through `Folders`/`Files` (each authorizes), and matches decrypted names case-insensitively in Go; 2–100 runes, sorted by lowercase name then path, capped by the caller (HTTP: 200). `TestSearchScale` pins 50 000 names; move to an index only if that is measured too slow, and never one that reveals name substrings.
- `FolderTree` (`zip.go`) reads a live folder and its live descendants in one transaction after a read check on the workspace, with paths built from decrypted names rooted at the folder's name. When M3 adds folder or file grants, it must recheck every member.
- Upload sessions (`uploads.go`) belong to their creator, expire 24h after start, and are capped at 8 open per user and at the caller's `max` and free quota at start (`Publish` rechecks quota). Every call rechecks edit access. Each append is sealed in the blob format to its own `<staging>/<session>/<uuid>` segment (via `.part-*`, fsynced) before one transaction advances `received` from exactly `start`; the loser of a race deletes its segment. Staging never holds plaintext. `CompleteUpload` first claims the session (`completing`, one conditional UPDATE) so only one completion re-seals at a time; a second gets `ErrConflict` before writing anything, a failure releases the claim, and a crashed request's claim expires after 30 minutes. It streams the segments through `WriteBlob` and `Publish`, then deletes the session and its directory; a failed publish removes the new blob. `ExpireUploads` drops expired sessions and hour-old staging directories with no session. Staging is not user data: outside backups, safe to delete. Only start and cancel write events; the version event comes from `Publish`.

- Editor document keys are `<file>-<revision>` at epoch 0 and `<file>-<revision>e<epoch>` after a cross-workspace move or a user revocation (`DocumentKey`, `ParseDocumentKey`); sessions store the key's base revision and epoch so revocation drops target the key they opened. `EditorSession` joins an open (`closed=false`) document whose `current_revision` is the file's revision at the current epoch, so a force-save never splits co-editors across keys; a key closed without saves (`CloseEditor`, Euro-Office status 4) reopens. `EditorDownload` serves the document's `current_revision`; the caller verifies Euro-Office's signature, the session row holds no download credential. Editor revision pointers and save digests make force-save sequences atomic: a save is a duplicate only when its digest is the document's newest save, so A, B, A publishes A again. Competing uploads conflict; session rows survive user deletion for revocation delivery.
- `RevokeUserEditors(ctx, tx, user)` revokes a user's editor sessions and bumps `editor_epoch` on their files inside the caller's transaction (nil store is a no-op); `internal/store` calls it wherever it revokes an account's sessions. Other users still on the old key keep saving to it; new openers get the new key, so whichever document saves second conflicts.
- Session expiry (12h) gates downloads only. `CallbackActor` ignores age; the sweep in `PendingRevocations` revokes an expired session once its document is closed, or `editorGrace` (7 days) after expiry if Euro-Office never closes it, so a connected editor is not dropped mid-edit and purge is never blocked for good. Drops are retried in `next_attempt` order; `DeferRevocation` backs a failed drop off from 2s doubling to 1h, so failing drops queue behind new ones.
- Roll back only to a version that understands personal ownership after private workspaces are created; earlier versions do not provide personal access or filtering.
- Service credentials are hashed, workspace-scoped reader/editor grants tied to current issuer membership and expire after 90 days.

## Verification
- `go test -race ./internal/drive` covers concurrent saves, offboarding, quotas, atomic memberships and editor replay/conflict; `schema_test.go` (migrations, legacy upgrade), `trash_test.go`, `move_test.go`, `purge_test.go`, `retention_test.go` and `handover_test.go` cover the file-management contracts; `sealed_test.go` (round trip, every seek offset, tampering) and `seal_legacy_test.go` (swap, crash rerun, purge/copy races) cover blob encryption; `editor_test.go` covers account-security revocation and key rotation, expiry versus open documents, force-save key sharing, A-B-A saves, drop backoff, the orphan sweep, the quota index and drive-wide trash retention; `changes_test.go` covers the change row of every mutator, rollback, seq order, pruning, current-state dedupe, 410 cursors and snapshot-then-changes completeness; `devices_test.go` (`TestDeviceLink`, `TestDeviceToken`) covers every redirect, code and token refusal, the 20-device cap, revocation with wipe, pruning and the device context's refusals; `names_test.go` covers the populated-database name migration (raw file and WAL hold no plaintext), conflicts on every name write, bytewise order, wrong and missing keys.
