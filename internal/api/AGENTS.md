# API

## Purpose
Exposes HTTP REST routes, authentication endpoints, Single Sign-On callbacks, SCIM endpoints, backup restore drill handlers, and static React PWA hosting.

## Ownership
Owns HTTP routing, request parsing, session cookie validation, CORS headers, and error response formatting.

## Local Contracts
- `ApplyInstaller` is a private Unix-socket callback, never a public route. It validates desired configuration before transactional writes and reports restart pending until the running snapshot matches. Dedicated installer administrators cannot create personal workspaces, access files/editor sessions or mint service credentials; shared-workspace management and the guest-link and computer policies (`allowInstallerActor` allowlist) remain available. Existing mixed-use accounts require explicit migration.
- `GET|HEAD /livez` (alive, no database) and `/readyz` (`health.go`: not draining and a database ping within one second, cached for one second behind a lock; 503 `unready` otherwise) send `Cache-Control: no-store` and only a status word. `Drain` turns `/readyz` 503 for good; `cmd/server` calls it at SIGTERM and keeps serving for `ReadyDrain` before shutting down (`TestLivezAndReadyz`, `TestDrainTurnsReadyzUnready`).
- `GET /healthz` reports `clientIp`, `proxyHeadersTrusted` and `scheme` from the same peer allowlist used by authentication. Installer ownership/configuration rows are omitted from `/api/settings`.
- KyIdentity sign-in (`sso_handlers.go`): the PKCE verifier and nonce ride in `ky_pkce_<state>` / `ky_nonce_<state>` cookies (Path `/`), named `__Host-…` like the session cookie when `CookieSecure` and no `KY_COOKIE_DOMAIN`, so a sibling subdomain cannot plant a pair for its own code (`TestSSOFlowCookiesAreHostOnly`).
- Step-up (`step_up.go`): `POST /api/auth/app-passwords` (WebDAV passwords and agent tokens), `POST /api/drive/workspaces/{id}/tokens`, `POST /api/devices/approve`, `POST /api/devices/phone-code` and `POST /api/drive/{files|folders}/{id}/guest-links` are wrapped in `requireStepUp`: the cookie session's `step_up_at` must be within 5 minutes (`stepUpWindow`, `Server.now`), else 403 `{"error","code":"step_up_required","method":"password"|"sso"}`; a Bearer caller has no session and gets the same refusal. A local password sign-in starts stepped up. `POST /api/auth/step-up` `{password}` (session + CSRF, local password accounts only, 409 `step_up_sso` otherwise) re-proves under the login limits (20 per minute per client, 10 per 15 minutes per account and client, then 429), 403 for a wrong password; KyIdentity accounts use `GET /api/sso/kysignon/login?step_up=1&return=<path>`, which needs the session, sends `max_age=0`, and whose callback requires the session's own subject and an `auth_time` no older than the flow's start (one minute of skew; the start and return path ride in a `ky_stepup_<state>` cookie MACed with the session secret and bound to the state, so a forged or re-stated cookie, or a flow older than 6 minutes, is a 400), dates the step-up from `auth_time`, signs nobody in and redirects to the same-origin path (else `/`). Both audit `auth.step_up` (`method=`). Listing, renaming scope and revoking stay plain session routes. `step_up_test.go`.
- POST `/api/auth/change-password` accepts a local password account's session (restricted or not: a forced replacement or the owner's own change; 409 for accounts without a local password), current password and a different policy-valid new password; the audit details say which (`TestLocalAccountChangesItsOwnPassword`). Browser CSRF and per-IP/account limits apply. Success revokes all sessions and requires sign-in again; flagged sessions get `password_change_required` on protected routes and public-only settings.
- No local MFA: two-factor sign-in is KyIdentity's. There are no `/api/auth/mfa/*` routes, and `POST /api/auth/login` issues the session after the password whatever `users.totp_enabled` says; the stored TOTP and recovery-code columns stay, unused (`mfa_test.go` `TestLocalMFAIsGone`).
- `GET /api/auth/me` includes `open_in_new_tab` and, only when signed in, `version` (`appversion.String()`, for the About dialog). `PUT /api/auth/preferences` takes exactly `{"open_in_new_tab": bool}` from a session (CSRF-checked; service tokens and restricted sessions refused) and changes only the caller's own preference. `preferences_test.go` pins validation.
- All JSON API endpoints return structured errors `{"error": "message"}` upon failure.
- Non-API routes fall back to serving `web.Handler()` for client-side SPA routing; unmatched `/api/` paths return a JSON 404.
- New routes are unauthenticated only by deliberate choice; privileged ones are registered wrapped in one administrator class in `routes()`, so the trust level of every route is readable in one place. The classes (tenancy design, Admin surface; `TestAdminRoutesHaveTheirClass` pins each route's): `platformAdmin` (install-wide), `orgAdmin` (multi-tenant: `X-Ky-Org` naming a selectable org, else 400 `org_required`, bound with `drive.WithOrg` and each GET audited `staff.read` in that org; single-tenant ignores the header) and `singleTenantAdmin` (404 on a multi-tenant install, D10). Each wraps `requireAdmin`, which also requires `store.Administrator` (an active principal, and on a multi-tenant drive in the staff org, D9). A multi-tenant install answers `/scim/` 404.
- Multi-tenant export (`export.go`, `tenancy_export_test.go`): a verified `export_only` claim signs in only an existing same-org active member of a fresh, enabled `deletion_scheduled` org, with a session of at most one hour. The callback redirects to GET `/api/export` (404 in single mode), a bounded My-files zip containing `manifest.json`, trash and all retained versions; no shared-workspace/Shared-with-me, staff or query/header selector can expand it. The stream uses the existing blob reader and aborts rather than completing a short archive on read or session failure; it rechecks the session before every version. Only `/api/auth/me` (`export_only:true`) and logout accompany it; step-up and ordinary routes remain refused.
- Identity binding, multi-tenant (`sso_handlers.go`, `suite_orgs.go`; `tenancy_identity_test.go`): the callback refuses an ID token without `org_id` (403 "User account not provisioned"), checks the org with `orgActive` (one synchronous `pollOrgs` for an org not yet registered; not active or not enabled is 403 "Account is inactive", nothing created), refuses a known subject in another org (`inOrg`: same 403, audited `tenancy.org_mismatch` with `entry=`), and provisions an unknown subject in the token's org whatever `AutoProvision` says. Step-up requires the session account's org. Back-channel logout without `org_id` is 400; a subject-wide logout naming another org still applies, is audited and logged as an alert. `RunSuiteOrgs` (cmd/server, multi-tenant only) polls `suitedir.Orgs` every 60 s from `drive.OrgsSince` and applies pages with `drive.ApplyOrgs` under `orgsMu`, after `applyErased` has read `suitedir.Erased` from `store.ErasedSince` and applied each entry with `EraseDirectoryUser` (an entry naming an account in another org is skipped with an alert; a failed read fails the poll before the orgs, so a fresh org mirror means the erasures are applied; `tenancy_erasure_test.go`); a staff org listed as not active is logged as an alert and left active. `syncSuiteGroups` reads suite groups per org there (`drive.ActiveOrgs`, `suitedir.OrgGroups`), and `ApplyInstaller` is refused. A signed KyPost request without `org_id` is 400 `bad_body`, and one for an account in another org is 404 `no_user` and audited (`inOrg`, `entry=kypost`). `TestCrossOrgMatrix` calls every `/api/drive` route with an ID in its path as an org A member and as staff in org A, with each of org B's IDs and a random one, and requires the same answer.
- Backup routes and theme writes are admin-only: capsules and settings carry site data and secrets. Backup routes have no step-up; admin-only plus `TestPrivilegedEndpointsRequireAdmin` is its equivalent for every destructive backup route. Routes are registered with method patterns, and because the SPA catch-all answers any method, tests pin that a wrong method never reaches a backup handler rather than expecting 405.

- `POST /api/backup/deposit` is one `recoveryclient.Run`: seal once, deliver to the local directory and to KyRecovery when paired. 412 no key, key pin missing, no destination, no database snapshot, or a private destination with `KY_BACKUP_ALLOW_PRIVATE_RECOVERY` off; 409 key mismatch or a run in flight; 413 over the capsule caps; 502 when KyRecovery refused (`recoveryclient.ErrRemote`, naming a local copy that was written, so the `ErrPrivateDestination` arm must stay above it: the lib wraps both on the dial path); 500 for a failure before a byte left; 200 with `receipt_unrecorded` when the store holds the capsule but the receipt was not written. It runs on a context detached from the request with write deadline `backupWriteBudget` (collect limit + 16 minutes); payload collection runs on `s.collecting`, which `StopBackupCollection` (called by `cmd/server` at shutdown) cancels, since nothing has left the server yet; the acting admin is resolved before the upload and the audit row is written on that same detached context.
- The write-once, irreversible backup handlers (`handlePairRemoteRecovery`, `handlePinKey`, `handleRunBackup`) run on `context.WithoutCancel(r.Context())` so a dropped connection cannot leave a pin, a pairing or a deposit half-written with no audit row; the idempotent ones (`handleSetSchedule`, `handleSetBulkRetention`, `handleUnpair`) stay on the request context. Their routes are registered as `s.tracked(s.requireAdmin(s.handleX))`, so the `detached` counter is incremented the moment `ServeHTTP` dispatches -- before `requireAdmin`'s session lookup, which is itself a store round-trip that `ReadTimeout` (15s) lets outlast `shutdownTimeout` (5s). Registering inside the handler was too late: `Shutdown` returns after its timeout with requests still active, and one still in the auth lookup would leave `WaitDetached()` reading zero and the store closing under a request about to pin a key. The header-read window before `ServeHTTP` is entered cannot be covered by any counter, because no handler goroutine exists yet; `Shutdown`'s own drain is what covers it. The counter is a mutex and a `sync.Cond`, not a `sync.WaitGroup`, which panics when an `Add` from zero races an in-progress `Wait` -- two admin requests at SIGTERM do exactly that. `WaitDetached()` is what `cmd/server` blocks on before closing the store, because `http.Server.Shutdown` returns without knowing these goroutines exist.
- Audit actions: `backup.paired`, `backup.pair_failed`, `admin.backup_run` (details start with `outcome="success|failure"`), `admin.backup_unpair`, `admin.backup_key_pin`, `admin.backup_schedule`, `admin.bulk_retention`, `admin.backup_export` (a downloaded capsule, resource the capsule ID). `AuditDetails` flattens the lib's details map into the bounded audit field with locally derived fields first and remote error text last; values are quoted and `=` is escaped before the final `AuditSafe` cut. `cmd/server` uses it for the scheduler and CLI rows, including `backup.bulk_prune` (actor `system`, `outcome`, `forgotten`, `error`). Details carry key or capsule IDs, digests and paths, never the token.
- Login answers unknown, inactive and wrong-password attempts with the same 401 `Invalid credentials` after a real (or dummy-hash) password verification; status is checked only after a correct password. Besides the per-client `login:` window, `login-user:<lowercased username>|<client>` (`accountKey`: the client address, an IPv6 one by its /64) allows 10 attempts per 15 minutes and resets on a successful password; once exhausted it answers the same 401 `Invalid credentials` as a wrong password, and only to that client, so guessing from elsewhere never locks the owner out (DECISIONS: login lockout; `TestLoginLockoutIsPerClient`).
- Public `/api/settings` `sso_enabled` is true only when SSO is on and a KySignOn issuer and client ID are set (`KY_SSO_ENABLED` defaults on); the login page shows its SSO button only then (`TestPublicSettingsReportSSOOnlyWhenConfigured`). With `KY_SSO_ENABLED=false`, `/api/sso/kysignon/login` and `/callback` answer 404 even when a provider is configured; back-channel logout still works (`TestDisabledSSORefusesSignIn`).
- SSO and webhook failures to unauthenticated callers use fixed messages; detail goes to the log only.
- `GET /api/suite/apps` (`suite_apps.go`, session auth) answers `{"apps":[{id,name,url}]}` for the app rail: for a `kysignon` or `scim` account with a subject, ky-primitives `suitedir` asks KyIdentity `/api/suite/apps?sub=` with the effective `cfg.SSO` issuer, client ID and secret. Local accounts, SSO off or incomplete and any KyIdentity error answer `[]`; errors are logged without secret or sub and not cached. Lists are cached per local user ID for `suiteAppsTTL` (60 s), never across users; `no-store` to the browser. `TestSuiteApps`.
- KyPost (`kypost.go`, contract in `docs/KYPOST.md`): the link (`kypostLink`, an atomic peer, never logged) comes from `KYDRIVE_KYPOST_URL`/`_SECRET_FILE` or `suitedir.Peer("kypost")` (`StartKyPost`: 5 s at startup, hourly, retry from 1 min doubling, `no_peer`/unauthorized unlink, unreachable keeps, a bad signature on a KyIdentity link kicks a lookup at most once a minute). `kypostSigned` wraps `POST /api/suite/kypost/{upload-tickets,links,status,fetch}` (events `kypost.drive.{ticket,link,status,fetch}`): per-IP 600/min, `kypost_off`, event type then `syncauth.Verify` with a memory replay guard (replay 200 `duplicate`; 429 and 5xx forget the ID), `bad_body`, `kypostAccount` (issuer equals `KY_KYSIGNON_ISSUER`, `store.DirectorySubject`, active, not `InstallerAdministrator`, else `no_user`), per-user limit (60/60/120/60 a minute), the switch (`kypostEnabled`: stored choice, else on for a KyIdentity link, off for an environment one; not for status), then the handler under `peerContext` (`drive.WithPeer` with the switch default, `Pairing` = hex HMAC-SHA256 under the pair secret of `kydrive:kypost-pairing\0<source>\0<url>` binding tickets to their pairing, and a `Live` check that the same URL, source and secret are still linked; `ErrPeerGone` answers `kypost_off`, `ErrPeerOff` `sharing_off`). Only verified events are audited (`kypost.<route>`, `event:<id>`, `outcome=ok`/`refused=<code>`). `handleTicketUpload` (from `ServeHTTP`) takes whole or `Content-Range` chunks (≤ `chunkLimit`, `Content-Length` exact) for `Store.TicketUpload`, rechecks the switch and pairing, limits 240/min per IP and 600/min per owner, lifts the write deadline on the last chunk and answers 204 `Upload-Offset` or 201 `{file_id,name,size}`; the ticket is never logged or audited. The link route's `audience:"guest"` (contract K, `kypostGuestLink`) needs `guestPolicy` on and `Store.PeerGuestSetting` (else 409 `guest_links_off`) and `days` 1..`max_days` (else `bad_body`), makes `Store.PeerGuestLink` and audits `guest_link.created` with `peer=kypost`; status adds `guest_links`/`guest_max_days` (`kypostGuestAllowed`); `/api/drive/kypost` adds `guest_policy` and `guest_links` and PUT takes exactly one of `enabled` or `guest_links` (on refused 409 while the policy is off; audited `kypost.guest_switch`). `kypost_guest_test.go`. `kypostFetchRoute` (contract I2) streams a file `Store.PeerFetch` admits (`max_bytes` required, else `bad_body`; larger 413 `too_large`) through `kypostReply.serve`, audited `kypost.file_fetched`. Viewing copies (`kypost_view.go`): `POST /api/suite/kypost/view-tickets` (`kypost.drive.view`, 60/min, 409 `editor_off` without Euro-Office) and `handleViewUpload` (from `ServeHTTP` at `/api/suite/view/<ticket>`, no CORS, any `Origin` 403, one exact-length request, 60/min per owner, 240/min per IP, switch and pairing rechecked, 415 `bad_type`, audited `kypost.view_stored`); `/view.html` and `/view-bootstrap.js` (closes the copy on `pagehide`), `POST /api/drive/view-copies/{id}/editor` (owner session; view mode, every permission off, key `view-<id>`; audited `kypost.view_opened`) and `/close`, `GET /api/editor/view/{id}` (Euro-Office signature for that URL), and `editorCallback` hands `view-` keys to `viewCallback` (2/6 refused 403, 4 deletes). `revokeEditors` (the 2-second worker) also drops `PendingViewDrops` keys from Euro-Office. `RunRetention` runs `ExpireViewCopies` and sweeps `<data>/view` past 25 hours. - Picker (`suite_pick.go`, contract in `docs/SUITE.md`): `GET`/`POST /api/drive/pick` (session; under `/api/drive/` so dedicated administrators are refused). `pickApp` accepts only an `origin` exactly equal to the `https` origin of an app URL in `userSuiteApps` (the cached KyIdentity list, `suite_apps.go`), and `copy` only for the paired KyPost origin with the user's switch on. POST (30/min per user, ≤20 files) is all or nothing: link mode makes reader organisation links through `CreateLink` (expiry by `linkExpiry`, shared with the KyPost link route) and revokes them if a later file fails; copy mode calls `Store.RecordPicks`. Each file carries `mime` only from `pickType` (the name's `mime.TypeByExtension`, bare, matching `pickMime` and ≤127 bytes), else none. Audited `suite.pick` per file with IDs only. `/pick` itself is the SPA under the global headers (no COOP). `suite_pick_test.go`.
- POST `/api/sso/kysignon/backchannel-logout` is anonymous; the KySignOn-signed `logout_token` (form, ≤16 KiB, `Cache-Control: no-store`) is its authority. A `sid` ends that login's sessions and fences the `sid` for ten minutes (`store.SSOLogoutFence`) so an in-flight callback answers 401; a `sub`-only token ends the subject's sessions whose ID token was issued before `iat` + 1s and fences that cutoff for ten minutes by provider and subject, so an in-flight callback, including a first login still provisioning, also answers 401. 200 on success, replay or unknown subject, 400 `invalid_request` for any token that fails verification; audited `auth.sso_backchannel_logout`. It is deliberately not rate limited: a KyIdentity restore sends one logout per login at once, and a 429 would exhaust its retries. `TestBackchannelLogoutEndsTheSSOLogin` covers the sid, fence, subject-wide (including a pending first-login callback), replay and ID-token-confusion paths. `requireAuthenticated` passes the cookie session to the drive as `drive.WithLogin`, so editor sessions stay bound to their login; `TestBackchannelLogoutRevokesEditorsOfPrunedSessions` opens an editor through an SSO login, prunes the expired browser session and checks both logout forms still deny the editor callback.
- Rate-limit keys for `login:` and `device-token:` come from `auth.ClientIP`, never from `RemoteAddr` or a raw header, so a limit is neither shared by everyone behind a proxy nor bypassable by forging `X-Forwarded-For`.
- Office networks (`KY_RATE_LIMIT_EXEMPT_NETWORKS` plus the `rate_limit_exempt_networks` setting, parsed together by `ky-primitives/netallow`) skip only these per-IP windows, through `allowPerIP` (WebDAV: `officeDraw` in `serveDAV`), which matches the `requestIP` result and nothing from a raw header: `login:` (sign-in and step-up), `password-change:`, and `dav:` for HTTP Basic app passwords only (device-token Bearer failures still count). Each keeps a per-account window. Office requests draw on one shared `officeBudget` per limit (`login:office`, `password-change:office`, `dav:office`; 200 a minute across all listed networks) and meet the per-IP window once it is spent; `exempted` counts only requests that actually skipped the window. The budget also bounds the account keys an office mints: sign-in plus WebDAV at 200 a minute for a 15-minute account window is 6 000, under `attemptsCap` (`TestOfficeBudgetFitsTheLimiter`), so office traffic cannot evict live account windows. Sign-in, step-up, password change and WebDAV all reserve the per-account window with `allowAttempt` before the lookup or hash, and hand it back (`refundAttempt`/`resetAttempts`) on success or an internal error, so concurrent guesses cannot outrun it. `refundAttempt` deletes a window it refunds to zero, so a lookup that fails without being a guess (a cancelled request) leaves no key behind (`TestRefundedOfficeDAVLookupsLeaveNoKeys`). `mcp:`, `device-token:`, `tls-pin:`, `link-open:`, `guest:` and `guest-upload:` have no per-account window and are never exempt; a new per-IP limiter goes through `allowPerIP` only when a per-account bound remains, and only if the budget sum above still fits `attemptsCap`. Admin-only GET/PUT `/api/settings/rate-limit-networks` (`{networks}`, reply `{networks, environment, exempted}`); a PUT validates before storing the canonical list, swaps the live list and audits `admin.rate_limit_networks`. A stored list that fails to load at startup is dropped for the environment list, never widened. `exempt_networks_test.go` pins each of these. Limiter windows run on the server clock `s.now` (`SetClockForTest`), so tests hold or pass them instead of racing the wall clock (`TestLimiterWindowsFollowTheServerClock`).
- Replica state (R4): in multi-tenant PostgreSQL `s.shared` (`store.Shared`) replaces every per-process security map and the WebDAV lock table: `allowAttempt`, `attemptsExceeded`, `refundAttempt` and `resetAttempts` (per-IP buckets, office budgets and account windows alike), spent PoW salts, the KyPost replay guard and device-signature nonces (`sharedReplay`, kinds `kypost` and `device:<id>`), and conversion tickets (no file name stored: `document.<ext>`). Each call has its own 5 s context (`onShared`); a failure is logged and refuses. Database time sets the windows, so `s.now` does not move them there. SQLite and single mode keep the maps. `shared_state_test.go` sends each hit or replay to a second replica on one database.
- CORS permits only the exact configured `KY_APP_URL` origin, reflected with `Vary: Origin` on every response, except `/api/suite/upload/<ticket>`, which answers exactly the paired KyPost origin (`PUT, OPTIONS`, `Content-Type, Content-Range`, exposing `Upload-Offset`, never credentials) and refuses any other `Origin` 403 `bad_origin` before the general block (`TestKyPostCORSIsTheTicketRouteOnly`); nothing sends `*`, `/mcp` gets no CORS headers, and `ServeHTTP` is the only code that sets them (`TestCORSNeverGrantsAnotherOrigin` walks the source). App password and agent token writes are cookie-session plus CSRF routes behind the same-site check (`TestAgentTokenWritesRefuseForgedCrossSiteRequests`). Every unsafe request except the HMAC-signed `/api/sso/kysignon/sync` is refused (403) when `Sec-Fetch-Site` is present and not `same-origin`/`none`, or `Origin` is present and not the `KY_APP_URL` origin; this covers the CSRF-exempt credential route (exactly `/api/auth/login`; `credentialRoute`), which also requires `Content-Type: application/json` (415). Session-cookie writes need the session-bound CSRF header (`internal/auth`). A Vite dev proxy therefore needs `KY_APP_URL` set to the proxy origin. `hardening_test.go` pins these, login uniformity, PoW single use and webhook status codes.
- API request bodies are capped at 1 MiB and all responses receive baseline CSP, anti-framing, MIME-sniffing, and referrer-policy headers.
- `GET /api/settings` tiers its payload: public fields for the login screen, `db_driver`/`scim_enabled` for any session, and `extra_settings` for admins only; KyRecovery tokens are omitted in both sealed and legacy plaintext forms, dropped by the `kyrecovery_token` key prefix rather than by literal key name.

- Sessions are cookie-only, so the CSRF check always covers them; `Authorization: Bearer` is accepted only on `/api/drive/*` (through `requireAuthenticated`, never an administrator class) and `/dav/`: a `kyd_` token is a linked computer's device credential (`drive.DeviceUser`, context marked `drive.WithDevice`), anything else a workspace-scoped service token (`/api/drive/*` only) (`TestSessionTokenIsNotABearerCredential`).
- Linked computers (`devices.go`): `POST /api/devices/approve` (session + CSRF, JSON `{redirect, challenge, state, name, platform}`, `state` 1-256 bytes) returns `{redirect}` = the loopback redirect plus `?code=&state=`; nothing approves on a GET. `POST /api/devices/token` is public (CSRF-exempt, same-site checked), reads form fields `code` and `verifier` from the body only (never the URL), allows 20 attempts per minute per client like login (429) and returns `{token, user_id, user, devices_url}` plus exact KyIdentity `issuer`/`sub` for directory accounts and `org_id` in multi mode (`user_id` is the account's immutable ID, `user` its username) or 400 for any refused code. A required `publicKey` (P-256 SPKI DER, std base64; missing, any other curve or bad encoding 400, the code unspent) enrols the device's signing key; it is the only way a key is enrolled. With `grant=qr` it reads `code`, `name` and `platform` (`android`/`ios`) instead and redeems a phone code (`drive.RedeemPhone`). `POST /api/devices/phone-code` (session + CSRF + step-up) answers `{link: kydrive://link?srv=<AppURL>&code=, expires_in: 120}` for a phone to scan (`TestPhoneQRLink`). `GET /api/drive/device` answers the same identity fields (without token/devices URL) for the presenting `Authorization: Bearer kyd_…` token only (a session or any other credential gets 401; a revoked token `deviceUser`'s 401), so a client can confirm which account a stored token belongs to (`TestDeviceAccount`). `GET /api/devices` and `DELETE /api/devices/{id}?wipe=true|false` (session + CSRF) list and revoke the caller's own devices; `DELETE` answers `{wipe}` and, when `drive_device_wipe_locked` is true, forces `drive_device_wipe_default` whatever the request says. `DELETE /api/devices/self` is the client's own unlink: authenticated only by its `Authorization: Bearer kyd_…` token (a session, service token or app password gets 401; CSRF-exempt because no browser sends that header ambiently, same-site still checked), it revokes exactly that device with `wipe=false` whatever the request says (`drive.UnlinkDevice`, event `device.revoked`) and answers 204; a revoked or unknown token gets `deviceUser`'s 401, so a repeat answers `device_revoked` with `wipe:false`. These routes and app passwords refuse dedicated installer administrators (`credentialActor`). `GET /api/drive/device-policy` (`requireAuthenticated`) and `PUT` (`requireAdmin`, both fields required, audits `admin.device_policy`) carry `{wipe_default (unset true), wipe_locked (unset false)}` in `server_settings`. A revoked device token answers 401 `{"error":"device_revoked","wipe":bool}` for 30 days, everything else unusable a plain 401; a dedicated installer administrator's token gets 403. Orgs `BeginReports` could not freeze, and any ID that is not a lowercase UUID (KyIdentity refuses a whole batch for one), are left out and logged; the rest are still sent (`TestStorageReportsSurviveABadOrg`). A stale answer is logged `ALERT storage pool`. Byte-adding write handlers wrap their store publish/ticket calls in `drive.RetryPool` so concurrent writes wait out an in-flight report (`drive.ErrPoolRefreshing`) instead of answering 413 (`TestConcurrentWriteWaitsOutInflightStorageReport`).
- `RunSuiteOrgs` runs `purgeLifecycle` after every poll, failed ones included: `drive.PurgeOrgs` then `drive.EraseMembers`, removing the blobs (`blobRoot`) and viewing copies (`viewRoot`) each returns.
- `RunSuiteGroups` (`suite_groups.go`): at start and every `suiteGroupsPoll` (60 s), when `cfg.SSO` is enabled with issuer, client ID and secret (the `suite_apps.go` guard), `suitedir.Groups` then `drive.ReconcileSuiteGroups` into `drive.DefaultOrg`; multi-tenant, `suitedir.OrgGroups` and the reconcile once per `drive.ActiveOrgs` org (active and enabled). Any list error (5xx, 401, 404 `unknown_org`, network) is logged without secret or subjects and changes nothing in that org; the removal delay is one poll plus one pass. `cmd/server` waits for it on shutdown. `TestSuiteGroupsWorkerChangesNothingOnFailure`.
- `RunRetention` is a background loop (at start, then hourly) like `RunEditorRevocations`: it applies retention with the drive-wide trash age (an unreadable setting turns the trash purge off for that pass and logs) and then `SweepOrphans` with a 1h grace on the blob root and again on the thumbnail root, `ExpireUploads` and `PruneChanges`; `RunBlobSealing` runs `drive.SealLegacyBlobs` and then `drive.UpgradeBlobs` (KYB1 to KYB2, `blobUpgradeRate`) the same way. `cmd/server` waits for all three before closing the store.
- Uploads, templates and editor saves go through `drive.WriteBlob` with the deployment key; downloads go through `drive.OpenBlob` and `http.ServeContent`, so Range requests decrypt only the chunks they touch. A blob that fails authentication is 503, never served. `GET /api/backup/status` carries `key_in_data_dir`.

- `objects.go` selects S3 stores and staging trees by the org's immutable home. Configuration errors are fatal before the listener starts; legacy sealing/format upgrades run only on local single-tenant files. `purgeLifecycle` retries every deleted org prefix, including already-purged tombstones.
- Hosted search (`search_hosted.go`) loads a bounded immutable sealed snapshot into RAM for each request/batch, with org-specific keys and scoped file enumeration. Publish writes a new object before CAS, then removes the old object; failures preserve shared queue work. Cache entries contain ciphertext only and are evicted on local purge. A cold replica reads the committed pointer and retries a missing snapshot up to twice to cover concurrent replacement during HEAD/GET. The elected worker tails changes each poll and reconciles each org at startup and hourly, once across a forced multi-batch drain; only successful passes advance its worker-owned timer. `search_hosted_test.go` exercises real S3 with the CI `KY_TEST_S3_*` fixture, including multi-cell isolation, staged uploads, failed publication, replay refusal and purge.
- Regional KyPost pairing resolves each account via `suitedir.Peer.URLFor(home_region)` with no default-region fallback. Ticket preflight accepts served cell origins; the ticket upload narrows it to its owner's cell before acting. Pairing bindings include that cell's URL.

- Vault control-plane routes (`vault.go`) require a signed linked device and both configured
  keys. Receipts attest committed records. A check requires an exact, fresh witness checkpoint
  and live vault membership. The optional browser origin gets credential-free CORS on vault
  device exchange and vault API routes. Browser approval uses the exact configured callback

- Vault version bodies are streamed ciphertext. Device signing covers the body digest and the

  binding, device and role. It checks either a bound room or a signed blob reservation,
  with the current head and device, before the gateway forwards traffic. The fixed relay
  checkpoint route takes one `KyDrive-Checkpoint-Blob` header, reserves quota before reading,
