# API

## Purpose
Exposes HTTP REST routes, authentication endpoints, Single Sign-On callbacks, SCIM endpoints, backup restore drill handlers, and static React PWA hosting.

## Ownership
Owns HTTP routing, request parsing, session cookie validation, CORS headers, and error response formatting.

## Local Contracts
- `ApplyInstaller` is a private Unix-socket callback, never a public route. It validates desired configuration before transactional writes and reports restart pending until the running snapshot matches. Dedicated installer administrators cannot create personal workspaces, access files/editor sessions or mint service credentials; shared-workspace management remains available. Existing mixed-use accounts require explicit migration.
- `GET /healthz` reports `clientIp`, `proxyHeadersTrusted` and `scheme` from the same peer allowlist used by authentication. Installer ownership/configuration rows are omitted from `/api/settings`.
- POST `/api/auth/change-password` accepts a restricted local session, current password and a different policy-valid new password. Browser CSRF and per-IP/account limits apply. Success revokes all sessions and requires sign-in again; flagged sessions get `password_change_required` on protected routes and public-only settings.
- MFA enrolment is a session route (`requireAuthenticated`, CSRF-checked, local password accounts only; directory accounts get 409). POST `/api/auth/mfa/enroll` stores a sealed pending secret (`totp_enabled` stays false) and returns `{secret, otpauth_uri}`; 409 while enabled. POST `/api/auth/mfa/enroll/confirm` `{code}` validates against the pending secret, spends its counter, enables and returns 10 recovery codes once. POST `/api/auth/mfa/disable` `{password, code}` needs the password and a TOTP or recovery code. Confirm and disable allow 5 attempts per user per 5 minutes; enable and disable revoke every other session and all MFA challenges and audit `auth.mfa_enabled`/`auth.mfa_disabled`. `mfa_test.go` pins the flow.
- `GET /api/auth/me` includes `open_in_new_tab`. `PUT /api/auth/preferences` takes exactly `{"open_in_new_tab": bool}` from a session (CSRF-checked; service tokens and restricted sessions refused) and changes only the caller's own preference. `preferences_test.go` pins validation.
- All JSON API endpoints return structured errors `{"error": "message"}` upon failure.
- Non-API routes fall back to serving `web.Handler()` for client-side SPA routing; unmatched `/api/` paths return a JSON 404.
- New routes are unauthenticated only by deliberate choice; privileged ones are registered wrapped in `s.requireAdmin` in `routes()`, so the trust level of every route is readable in one place.
- Backup routes and theme writes are admin-only: capsules and settings carry site data and secrets. The scaffold has no step-up; admin-only plus `TestPrivilegedEndpointsRequireAdmin` is its equivalent for every destructive backup route. Routes are registered with method patterns, and because the SPA catch-all answers any method, tests pin that a wrong method never reaches a backup handler rather than expecting 405.

- `POST /api/backup/deposit` is one `recoveryclient.Run`: seal once, deliver to the local directory and to KyRecovery when paired. 412 no key, key pin missing, no destination, no database snapshot, or a private destination with `KY_BACKUP_ALLOW_PRIVATE_RECOVERY` off; 409 key mismatch or a run in flight; 413 over the capsule caps; 502 when KyRecovery refused (`recoveryclient.ErrRemote`, naming a local copy that was written, so the `ErrPrivateDestination` arm must stay above it: the lib wraps both on the dial path); 500 for a failure before a byte left; 200 with `receipt_unrecorded` when the store holds the capsule but the receipt was not written. It runs on a context detached from the request with a 16-minute write deadline; payload collection runs on `s.collecting`, which `StopBackupCollection` (called by `cmd/server` at shutdown) cancels, since nothing has left the server yet; the acting admin is resolved before the upload and the audit row is written on that same detached context.
- The write-once, irreversible backup handlers (`handlePairRemoteRecovery`, `handlePinKey`, `handleRunBackup`) run on `context.WithoutCancel(r.Context())` so a dropped connection cannot leave a pin, a pairing or a deposit half-written with no audit row; the idempotent ones (`handleSetSchedule`, `handleSetBulkRetention`, `handleUnpair`) stay on the request context. Their routes are registered as `s.tracked(s.requireAdmin(s.handleX))`, so the `detached` counter is incremented the moment `ServeHTTP` dispatches -- before `requireAdmin`'s session lookup, which is itself a store round-trip that `ReadTimeout` (15s) lets outlast `shutdownTimeout` (5s). Registering inside the handler was too late: `Shutdown` returns after its timeout with requests still active, and one still in the auth lookup would leave `WaitDetached()` reading zero and the store closing under a request about to pin a key. The header-read window before `ServeHTTP` is entered cannot be covered by any counter, because no handler goroutine exists yet; `Shutdown`'s own drain is what covers it. The counter is a mutex and a `sync.Cond`, not a `sync.WaitGroup`, which panics when an `Add` from zero races an in-progress `Wait` -- two admin requests at SIGTERM do exactly that. `WaitDetached()` is what `cmd/server` blocks on before closing the store, because `http.Server.Shutdown` returns without knowing these goroutines exist.
- Audit actions: `backup.paired`, `backup.pair_failed`, `admin.backup_run` (details start with `outcome="success|failure"`), `admin.backup_unpair`, `admin.backup_key_pin`, `admin.backup_schedule`, `admin.bulk_retention`, `admin.backup_export` (a downloaded capsule, resource the capsule ID). `AuditDetails` flattens the lib's details map into the bounded audit field with locally derived fields first and remote error text last; values are quoted and `=` is escaped before the final `AuditSafe` cut. `cmd/server` uses it for the scheduler and CLI rows, including `backup.bulk_prune` (actor `system`, `outcome`, `forgotten`, `error`). Details carry key or capsule IDs, digests and paths, never the token.
- Login answers unknown, inactive and wrong-password attempts with the same 401 `Invalid credentials` after a real (or dummy-hash) password verification; status is checked only after a correct password. Besides the per-client `login:` window, `login-user:<lowercased username>` allows 10 attempts per 15 minutes across clients and resets on a successful password.
- SSO and webhook failures to unauthenticated callers use fixed messages; detail goes to the log only.
- Rate-limit keys for `login:` and `mfa:` come from `auth.ClientIP`, never from `RemoteAddr` or a raw header, so a limit is neither shared by everyone behind a proxy nor bypassable by forging `X-Forwarded-For`.
- CORS permits only the exact configured `KY_APP_URL` origin. Every unsafe request except the HMAC-signed `/api/sso/kysignon/sync` is refused (403) when `Sec-Fetch-Site` is present and not `same-origin`/`none`, or `Origin` is present and not the `KY_APP_URL` origin; this covers the CSRF-exempt credential routes (exactly `/api/auth/login`, `/api/auth/mfa/totp`, `/api/auth/mfa/recovery-code`; `credentialRoute`), which also require `Content-Type: application/json` (415). Session-cookie writes need the session-bound CSRF header (`internal/auth`). A Vite dev proxy therefore needs `KY_APP_URL` set to the proxy origin. `hardening_test.go` pins these, login uniformity, PoW single use and webhook status codes.
- API request bodies are capped at 1 MiB and all responses receive baseline CSP, anti-framing, MIME-sniffing, and referrer-policy headers.
- `GET /api/settings` tiers its payload: public fields for the login screen, `db_driver`/`scim_enabled` for any session, and `extra_settings` for admins only; KyRecovery tokens are omitted in both sealed and legacy plaintext forms, dropped by the `kyrecovery_token` key prefix rather than by literal key name.

- Sessions are cookie-only, so the CSRF check always covers them; `Authorization: Bearer` is accepted only as a workspace-scoped service token on `/api/drive/*` (`TestSessionTokenIsNotABearerCredential`).
- Guest links (`guest.go`): off until an administrator turns them on (`PUT /api/drive/guest-links-policy` `{enabled, max_days 1–365}`, default 30; `GET` for any signed-in user). `GET`/`POST /api/drive/{files|folders}/{id}/guest-links` (`{days, password, upload_only}`) return `{link, url}` with the token in the fragment `/g/#<token>`. The public routes `POST /api/public/links/view` (JSON), `/download` (form fields, so the browser downloads natively) and `/upload?name=` (raw body, `X-Link-Token`/`X-Link-Password` headers, 128 MiB) take the token in the body or a header, never the URL. They answer 404 while guest links are off, ignore sessions (CSRF-exempt, still same-site; a guest page's form post arrives with `Origin: null` because of `no-referrer`, and is accepted only on guest routes with the browser's `Sec-Fetch-Site: same-origin`), send `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow` and `no-store` (as does `/g/`), and limit failures to 20 per minute per client and 5 wrong passwords per 15 minutes per link (429). Each request reserves its attempt before the check and is refunded unless it fails, so parallel guesses cannot outrun the count. Uploads are limited to 60 per hour per client and answer an empty 201: a taken name is numbered, never reported.
- Organisation links (`drive_shares.go`): `GET`/`POST /api/drive/{files|folders}/{id}/links` (`{role: reader|editor, expires}`; `POST` returns `{link, url}` where the token is only in the URL fragment `/l/#<token>`), `DELETE /api/drive/links/{id}` (revokes and runs `PendingRevocations`), and `POST /api/drive/links/open` with `{token}` in the body. Failed opens are limited to 30 per minute per client IP (429). The token is never in a request line, a response other than creation, or a log.
- Sharing (`drive_shares.go`): `GET`/`PUT /api/drive/{files|folders}/{id}/shares` (`{principal_kind: user|group, principal_id, role}`; `PUT` adds or replaces that principal's role), `DELETE /api/drive/shares/{id}`, `GET /api/drive/shared-with-me`, `GET /api/drive/people?q=` (active accounts, never email), `GET /api/drive/folders/{id}/children` (any folder the user can read, however) and `PUT /api/drive/workspaces/{id}/sharing` (`{editors_share}`). Share changes run `PendingRevocations` at once, so a removed or lowered share ends an open editor without waiting for the ticker.
- `/dav` and `/dav/*` are dispatched in `ServeHTTP` before the generic OPTIONS/CSRF block to `serveDAV` (`dav.go`): cross-site requests refused (`sameSiteRequest`), HTTPS required unless `KY_ENV=development` (TLS, or `X-Forwarded-Proto` from a trusted proxy), then HTTP Basic with an app password only, never a cookie or Bearer token. A `PUT` with an `X-OC-Mtime` that `dav.Mtime` refuses gets 400 before its body is read. Failed sign-ins only are counted, 20 per minute per client IP and 10 per 15 minutes per username (429 with `Retry-After`); dedicated installer administrators are refused. `PUT` bodies are capped at `KYDRIVE_MAX_FILE_SIZE`, others at 1 MiB. One in-memory `webdav.LockSystem` per server.
- `GET`/`POST /api/auth/app-passwords` and `DELETE /api/auth/app-passwords/{id}` need a cookie session (service tokens never reach `/api/auth`) and refuse dedicated installer administrators; `POST` returns the secret once with the username and `<KY_APP_URL>/dav/`.
- `/api/drive/*` routes use a validated session or workspace-scoped service token; admin-only routes do not accept service tokens. Middleware places the validated actor in request context; domain code rechecks current membership inside mutations. Single-request uploads stream with a 128 MiB cap and resumable chunks (`PUT /api/drive/upload-sessions/{sid}`, `Content-Range: bytes start-end/total`) with a 64 MiB cap; other request bodies stay capped at 1 MiB. Resumable sessions (`POST .../workspaces/{id}/upload-sessions` `{parent,name,file,revision,size}`, `GET`/`DELETE .../upload-sessions/{sid}`, `POST .../{sid}/complete`) stage under `<data>/staging`, are capped by `KYDRIVE_MAX_FILE_SIZE`, and answer a chunk conflict with 409 plus `Upload-Offset` to resume from; the hourly retention pass expires them. `GET /api/drive/search?q=` returns `{results,truncated}` (200 max). `GET /api/drive/folders/{id}/zip` streams an uncompressed zip after refusing (413) a total above `KYDRIVE_MAX_ZIP_SIZE`; a member that cannot be read aborts the connection rather than closing a short archive.
- Change feed (`drive_changes.go`, both `requireAuthenticated`, sessions or a token for that workspace; installer administrators refused): `GET /api/drive/workspaces/{id}/changes?after=<seq>&limit=` (default and max 1000, else 400) returns `{changes: [{kind, id, removed, file|folder}], next, more}`; `410` (`drive.ErrGone`) means the cursor predates pruned rows and the client takes a new snapshot. `GET /api/drive/workspaces/{id}/snapshot?after=<id>&limit=` returns `{folders, files, head, next}`, `next` empty on the last page; the client follows `changes` from the first page's `head`. `GET /api/drive/workspaces` carries `head` per workspace. `RunRetention` prunes rows older than 90 days (`changeRetention`) after expiring uploads. `drive_changes_test.go` (`TestChangesAuthorize`: outsider, removed member, admin without a grant and a token for another workspace get 403; a moved-out file never names its destination).
- `GET /api/drive/files/{id}` returns file metadata (`id`, `workspace`, `parent`, `name`, `size`, `revision`, `mtime`, `editable`) for authorized workspace members.
- `GET /api/drive/files/{id}/preview` (`drive_preview.go`, reader rights, `HEAD` and `Range` through `http.ServeContent`) serves the current bytes inline only when `http.DetectContentType` of the first 512 plaintext bytes is on `previewTypes` (PNG, JPEG, GIF, WebP, PDF, MP3, WAV, Ogg, MP4, WebM, UTF-8 text); anything else, HTML and XML/SVG included, is 415. The name never decides. Responses carry the sniffed type, `Content-Disposition: inline`, `nosniff`, `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self'; media-src 'self'; style-src 'unsafe-inline'; frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN` (the app frames PDFs), `Cross-Origin-Resource-Policy: same-origin` and `no-store`. `TestPreviewServesOnlyTheAllowlist`.
- `GET /api/drive/files/{id}/thumbnail` (`drive_preview.go`, reader rights) returns `drive.Thumbnail` of the current blob as `image/png` with the preview headers, generated once and cached sealed in `<KY_DATA_DIR>/thumbs/<blob>` (an unreadable cache entry is regenerated; a failed cache write is logged and the thumbnail still served); `drive.ErrNoThumbnail` is 415. Raster images are thumbnailed in-process; `convertible` Office formats and PDF go through `officeThumbnail` when Euro-Office is configured (otherwise 415): at most two conversions at once, a random in-memory conversion ticket for that one file (`/api/editor/convert/{ticket}`, gone when the conversion returns or after 2 minutes), the Document Server's output fetched through `Fetch`, capped at 8 MiB and decoded by `drive.Thumbnail` like an upload. A conversion failure is logged and answers 415.
- `/api/editor/download/{session}` carries no credential in the URL: it requires Euro-Office's outbox JWT (`Authorization: Bearer`, HS256 with the editor secret) whose `payload.url` is exactly `<KYDRIVE_EDITOR_DRIVE_URL>/api/editor/download/{session}`, plus an unrevoked, unexpired session and current membership. The signed editor config expires after 10 minutes (`editorConfigLifetime`); Euro-Office checks it when the editor opens. `/api/editor/callback` trusts the verified JWT payload, restricts output origin/path, publishes via the persisted editor revision pointer, acknowledges exact retries and records status 4 (closed without changes) with `CloseEditor`.
- `GET /api/editor/convert/{ticket}` serves one file to the Document Server for a thumbnail conversion: the outbox JWT must name exactly that URL (`Download`), as for editor downloads, and the ticket must be live. `TestOfficeThumbnailsThroughTheDocumentServer`.
- POST `/api/auth/logout` returns 500 when the server session could not be ended (cookies are still cleared). Audit writes after an action has happened (`s.audit`, `auditBackup`) log a failure rather than fail the request.
- Editor sessions end with the account's credentials: password change, operator reset, sign-out (`EndSession`), MFA enable/disable, directory deactivation/deletion and role changes revoke them in the store transaction; the revocation worker then drops them and backs failed drops off (`DeferRevocation`). A blob that never became a version is removed with `discardBlob`, which logs a failed removal; the orphan sweep retries it.
- Euro-Office editor integration routes `docx`, `odt`, `txt`, `rtf`, and `md` to `documentType: word`, `xlsx`, `ods`, and `csv` to `documentType: cell`, `pptx` and `odp` to `documentType: slide`, and `pdf` to `documentType: pdf`.
- `/editor.html` scopes its CSP to the configured Euro origin and uses a same-origin bootstrap script. Operational status exposes pending editor revocations without credentials.

- `GET /excalidraw/fonts/Xiaolai/` serves files from `<KY_EXCALIDRAW_FONTS_DIR>/Xiaolai` only, unauthenticated like the embedded fonts, with no directory listings; unset returns 404 rather than the SPA shell. `excalidraw_fonts_test.go` pins confinement.

- POST `/api/drive/personal-workspace` idempotently ensures the authenticated account’s private workspace; service credentials are refused. GET workspace lists distinguish `kind: personal|shared` and exclude other accounts’ personal workspaces, even from administrative browsing.
- POST `/api/drive/workspaces/{id}/documents` accepts `{name, kind: document|spreadsheet|presentation|markdown|rtf|whiteboard, parent}`, adds the corresponding extension (`.docx`, `.xlsx`, `.pptx`, `.md`, `.rtf`, `.excalidraw`), and publishes a bundled blank template through the normal authorization/quota/version path. Templates are product-owned assets under `templates/`; DOCX uses minimal OOXML, XLSX/PPTX originate from the selected Euro-Office local blank fixtures with cleared core metadata, MD/RTF/Excalidraw use standardized blank formats.

- Purge handlers delete blobs (`drive.RemoveBlobs`) only after the metadata transaction commits; a failed removal costs disk space, never a version without bytes. Workspace listings include `trash_days` and `keep_versions`.
- `driveError` maps `ErrDenied` 403, `ErrNotFound` 404, `ErrGone` 410, `ErrInvalid` 400, `ErrConflict` 409 with the wrapped domain reason (`err.Error()`, e.g. `revision conflict: move to trash first`), `ErrQuota` 413; anything else is a generic 500.
- `RunRetention` is a background loop (at start, then hourly) like `RunEditorRevocations`: it applies retention with the drive-wide trash age (an unreadable setting turns the trash purge off for that pass and logs) and then `SweepOrphans` with a 1h grace on the blob root and again on the thumbnail root, `ExpireUploads` and `PruneChanges`; `RunBlobSealing` runs `drive.SealLegacyBlobs` the same way. `cmd/server` waits for all three before closing the store.
- Uploads, templates and editor saves go through `drive.WriteBlob` with the deployment key; downloads go through `drive.OpenBlob` and `http.ServeContent`, so Range requests decrypt only the chunks they touch. A blob that fails authentication is 503, never served. `GET /api/backup/status` carries `key_in_data_dir`.
